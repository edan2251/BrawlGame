## 1. 계획

- 사용자 결정("새 구조로 반영")에 따라 문서를 개정 구조로 고친 뒤 구현(세트 3라운드 2선승, 세트 패자만 선택, 폼·증강 경기 끝까지, 5세트 선승, 선택 최대 4, 초기 폼 경기당 한 번).
- 새 단계 `FormSelect`·`SetPick`, `MatchState`에 세트스코어·세트 번호·선택 수·선택지 4칸·초기 폼 선택. 레거시 규칙(`RuleSet.LegacyMatch`)은 CP16 흐름 그대로.
- 선택 입력: 점프/공격/대시/가드 = 1~4번(누른 틱), 시간 초과면 상태 난수.
- 선택 화면(`PickPanelView`): 고르는 쪽 절반에만 선택지, 고른 뒤 READY만.

## 2. 작업 기록

- 2026-11-02 문서 개정(D-049~D-057, 명세 10·00·01·06, CHECKPOINTS CP22~24, CLAUDE.md) 커밋·푸시.
- 구현, 컴파일 오류·경고 0. 새 흐름에서 기존 빠른 묶음 553개 그대로 통과(레거시 규칙 분리 덕분).
- CP22 테스트 8개 첫 실행 통과.
- CP22-11 봇 완주: 시드 3에서 한 라운드가 32분 넘게 끝나지 않음. 원인: 봇이 폼을 바꿀 때마다 봇 객체를 같은 시드로 다시 만들어 행동 상태기·난수가 매번 처음으로 돌아가 같은 첫 행동만 반복. 튜닝 1회: 봇을 다시 만들지 않고 매 틱 파이터의 폼을 읽게 함(S-156). 6시드 모두 완주.
- 캡처 확인: 선택 화면에서 큰 가운데 문구가 오른쪽 선택 목록 첫 줄을 가림 → 선택 단계에서는 아래 작은 문구로(S-155).
- 새 구조와 충돌: 해당 없음(이번 CP가 새 구조).

## 7. 인계 사항

- 선택지 생성 `MatchFlow.BuildOptions`가 `Augments.AddCandidates`를 부른다(지금은 비어 있음). CP23은 `Augments`를 채우고 `MatchFlow.Apply`의 증강 분기를 쓴다. 증강 목록은 `FighterState.Augments`(4칸, 경기 끝까지).
- 선택 화면의 증강 이름은 `MatchPresenter.PickPanel.AugmentName`.
