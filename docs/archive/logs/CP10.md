## 1. 계획

1. F-1 천장 순간이동: `FighterPush`의 "위에 선 쪽" 분기가 천장을 확인하고, `ResolveX`는 이번 틱에 가로로 들어간 상자만 막는다. 재현 경기와 단위 테스트, 봇 불변식 점검을 회귀 테스트로.
2. F-2 효과음: 전체 볼륨 여유 + 최종 출력의 부드러운 리미터(AudioListener의 `OnAudioFilterRead`). 봇 영상 녹화도 같은 계산을 써서 게임과 영상의 소리를 맞춘다.
3. 디버그 표시: 빌드에서는 상태 글자와 틱·설정 줄을 기본으로 숨기고 키 하나로 켠다. 에디터는 지금처럼.
4. 모드 정리: 기본 모드 A, 빌드의 F1 순환에서 테스트 공격 모드 제외, 모드 B 동결 표시.
5. 검증: CP10-1~5, 빌드 첫 화면 캡처와 키 입력 후 캡처.

## 2. 작업 기록

- 2026-10-31 시작 전 MCP 확인: `read_console` 응답, 오류·경고 0, 에디터 준비됨. CR-001 명세 반영 커밋(`a0cee34`) 뒤 시작.
- F-1: `FighterPush`의 "위에 선 쪽" 분기를 `TryStack`으로. 위 파이터를 올릴 자리가 천장과 겹치면 천장 아래에 두고 아래 파이터를 그만큼 내리며 위로 가던 속도를 멈춘다. 둘이 쌓일 높이가 없거나 아래 파이터가 히트스탑 중이면 옆으로 밀어내는 규칙으로 넘긴다. `ResolveX`는 출발 x(`fromX`)에서 이미 가로로 겹쳐 있던 상자는 막지 않는다. 잡기·뒤 던지기 배치는 잡은 쪽 x를 출발점으로.
- 처음 만든 천장 판정은 "몸 중심보다 위의 상자"였는데, 단위 테스트에서 위 파이터 중심이 천장 아랫면까지 올라간 경우를 놓침 → 옮기기 전 높이를 기준으로 바꿈(시도 2회).
- 수정 뒤 QA 점검 다시: 144경기 103만 틱(두 모드, 두 프리셋)에서 경기장 이탈 1430 → 0, 지형 속 0. 같은 시드로 이전 코드는 "A 잡기 켬 Pit"에서만 49번 이탈했다.
- F-2: `SfxMaster`(볼륨 여유 0.6, 무릎 0.8 위 tanh 리미터), `OutputLimiter`(AudioListener 오브젝트의 `OnAudioFilterRead`), `SfxPlayer`가 볼륨에 여유를 곱함. 봇 영상 녹화도 같은 함수로 섞음. 리미터 테스트 첫 실행에서 "1 미만" 단정이 float 반올림(tanh → 1.0)에 걸림 → 기준(CP10-3 "1 이하")대로 고침.
- 디버그 글자: 빌드는 꺼진 채 시작, F12로 전체 켜기·끄기. 꺼져 있어도 입력 기록·재생 중에는 설정 줄(REC·REPLAY)만 보인다. 에디터는 켠 채 시작(시나리오 캡처 변화 없음).
- 모드: 코드 기본값 Charge, 빌드 F1은 A ↔ B만(테스트 공격은 에디터 전용), 설정 줄과 도움말에 B "frozen" 표시. `PLAYTEST.md` 단축키 표에 F12.
- 봇 영상: 한 편 시험 녹화가 16편 목록(`index.md`)을 덮어써서 시험 녹화는 목록을 건드리지 않게 고친 뒤 16편 다시 녹화.
- 빌드 키 입력 확인: 가상 키 코드만 보낸 첫 시도는 Input System이 받지 않음(스캔 코드 0) → 스캔 코드(` 0x29, F12 0x58)를 넣어 성공.
