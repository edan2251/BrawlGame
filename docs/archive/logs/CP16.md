## 1. 계획

사용자 지시로 순서를 둘로 나눈다. **1부(관문)**가 통과하기 전에는 2부를 만들지 않는다.

1. (1부) 접촉 해법 핵심: 웜 스타트(상태에 저장), 서브스텝 부드러운 접촉, 마찰, 잠들기·깨우기. 테스트 장면은 테스트 코드 안의 상자 한 줄 쌓기.
2. (1부) 확인: 6단 기둥 3600틱 안정성, 잠들기 기준, 저장·복원·결정론·SyncTest(붕괴 장면 포함), 롤백 8틱 시간(상자 40개).
3. (1부) CP15 보정(강체끼리 예측 접촉, 줄 위치 보정)이 쌓기에 맞는지 먼저 판단해 아래 2절에 적는다.
4. (2부) 맵 배치(ImplementedStage 3), 부분 붕괴, 캐릭터가 올라서도 안 무너짐, 상자 피해 상한, 연출(밝기 차·이음매), 대칭, 측정, 캡처.
5. 설계 변경 두 번 뒤에도 1부가 안 되면 멈추고 선택지(기둥 낮추기·상자 줄이기, 잠들기 강화, 부서지는 더미, Box2D 도입)를 묻는다.

## 2. 작업 기록

- 2026-11-01 시작. MCP 연결 확인(`read_console` 정상, 예전 웹소켓 재연결 경고만).
- **CP15 보정이 쌓기에 맞는지 판단**
  - 강체끼리 예측 접촉(속도로 넓힌 틈도 접촉으로): **방향은 맞음, 그대로는 안 맞음.** 서브스텝마다 접촉을 새로 찾아 충격량이 매번 0에서 시작하므로 웜 스타트를 이어 쓸 수 없고, 지형 접촉은 예측 없이 Baumgarte(오차 20%를 속도로) + 반발 목표 속도를 섞는다. 6단 기둥은 위 상자 무게가 아래로 전해지는 데 반복이 많이 필요해 웜 스타트 없이 버티기 어렵다. → Box2D v3처럼 **틱마다 한 번** 접촉을 찾고(예측 거리 = 속도 × 틱 + 0.02, CP15의 생각 유지), 서브스텝 동안은 몸의 이동량으로 틈을 갱신하며, 지형·경계·강체 접촉을 모두 같은 부드러운 제약으로 푼다. 반발은 CP15의 "풀이 뒤 반발 단계"를 모든 접촉에 넓힌다.
  - 줄 위치 보정: 줄로 이은 몸끼리만 작용하고 상자에는 줄이 없다. 쌓기와 부딪히지 않으므로 **그대로 둔다**(위치 보정은 몸의 이동량에 들어가 접촉 틈 계산에도 자연히 반영됨).
  - 잠든 몸은 풀이에서 **움직이지 않는 몸(질량 무한)**으로 다룬다. 지금은 잠든 몸에도 충격량을 더했다가 틱 끝에 지워 같은 틱의 다른 접촉 풀이를 흐렸다.
- 해법 교체(S-135): 틱마다 한 번 접촉 탐색 + 서브스텝 부드러운 제약 + 웜 스타트(상태 `PropBody.Warm`, S-136) + 이완 + 반발 단계, 상자 접촉점은 면 자르기 2점. 기존 구조물 테스트 84개 그대로 통과.
- 관문 1차: 6단 기둥 흔들림 0.0015~0.0046(통과). 실패 3건: ① 같은 폭 기둥 잠들기 62~70틱, ② 상자 40개 Step 0.56 ms·롤백 9.4 ms(파이터 무작위 입력으로 39개 깸), ③ 붕괴 장면 밀기 부족(테스트 장면). 함께 찾은 것: 경계 바닥에 세운 파이터가 경계 피해로 2086틱에 KO → 라운드 재시작(S-140).
- 설계 변경 1(S-137): 아래 상자가 먼저 잠들면 위 상자가 0.06 튀어 올라 잠들기가 되돌려짐 → 밀고 있는 접촉으로 맞닿은 몸끼리 함께 잠들기. 다시 잠들기 62 → 29틱.
- 접촉 풀이 1회(Box2D 기본)는 같은 폭 기둥 흔들림 0.014·Mobile 거울 오차 0.045로 4회 유지(S-136).
- 설계 변경 2(S-139, 성능): 몸 정보 배열 캐시, 연결 몸 목록, 접촉 풀이 스칼라화. 상자 40개(깨어 11) 물리 0.46 → 0.14 ms.
- **관문 결과(통과)**: `PropStackTests` 8개 + 구조물·경계 테스트 92개 전부 통과.
  - 6단 기둥 3600틱: 맨 위 가로 흔들림 혼합 0.0015 / 같은 폭 0.0045(기준 0.02), 겹침 0.015 / 0.023(0.05), 내려앉음 0.07 / 0.09(부드러운 접촉 6층), 에너지 증가 없음, 1초 뒤 각속도 0.0005 이하. 잠들기를 끈 설정도 같음.
  - 잠들기: 깨어난 채 시작 51~53틱, 다시 깨운 뒤 29틱에 모두 잠듦(기준 60).

## 6. 알려진 문제와 미룬 것

- 무너진 뒤 비스듬히 기댄 잔해 더미가 잘 안 나온다(4절). 사람 플레이(CP17)에서 아쉬우면 쳐낼 때 위 상자에 작은 회전을 주는 등으로 조정.
- 상자 40개를 모두 깨운 최악 장면은 롤백 2.9 ms(09 8절 가정 밖). 맵에는 상자가 11~17개뿐.
- 맵 거울 시험은 양쪽에서 가운데 구조물을 동시에 치는 경우를 뺀다(번호 순서 풀이의 한계, S-134·S-143).
- 도달성 탐색 테스트(CP8-1)가 경우마다 약 1분으로 느려 전체 EditMode가 약 10분.
- 깨어난 기둥은 부드러운 접촉으로 0.07~0.09 내려앉는다(겹침 기준 안).

## 7. 인계 사항

- CP17(모드 A 다듬기와 비교 빌드 v2)은 새 세션에서 시작. CP17 끝이 계획된 질문 지점.
- 구조물 해법: `PropPhysics`(틱마다 접촉 찾기 → 서브스텝 soft step → 반발 → 웜 스타트 저장, 두 점 접촉은 두 순서 평균). 반복 횟수: 연결 4, 접촉 1(+이완 1).
- 상자 규칙: 쳐냄 위력 24·속력 12·20틱(`PropParams.Knockout*`), 상자 피해 60틱 18(`BoxDamage*`). CP17 눈덩이 측정에 상자 피해(`BoxHit` 이벤트)를 함께 기록할 것.
- MCP: 이 PC에 Unity 인스턴스가 둘(Project_Brawl, Cursor-Dash-master) 붙을 수 있다. 도구가 인스턴스를 물으면 `Project_Brawl@...`을 지정.
