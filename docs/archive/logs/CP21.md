## 1. 계획

- 입력 비트 `SwitchForm`(6번째 비트). 누를 때마다 보유한 다음 폼(가위 → 바위 → 보). 자유 상태(공격을 시작할 수 있는 상태)에서만, 같은 틱 공격은 새 폼으로.
- 시작 보유 폼 `RuleSet.OwnedForms`(기록 문자열 끝 " o7"). 게임 실행은 CP22 선택 전까지 세 폼 모두 보유.
- 전환 지표(`SwitchMetrics`, Game 계층), 현재 폼 표시 세 방식(HOME), 바위 선딜 연출, 봇 전환(상대를 이기는 폼으로 틱마다 1/30).

## 2. 작업 기록

- 2026-11-02 구현, 컴파일 오류·경고 0. 키: P1 R, P2 Num5, 패드 RB(S-154).
- 시나리오 필드 `form2`, `owned`, 입력 이름 `Switch`. showcase `showcase_cp21_forms`.
- 첫 PlayMode 실행에서 새 테스트가 캡처 폴더가 없어 실패 → 폴더를 만들게 고침, 재실행 통과.
- 무작위 입력 생성기는 기존 5비트 그대로(기존 무작위 시험의 입력이 바뀌지 않게).
- **새 구조(경기 구조 검토)와 충돌하는 구현: 없음.** 단, 시작 보유 폼은 라운드마다 `RuleSet`에서 다시 적용된다(CP22 범위). 새 구조에서는 경기 끝까지 유지·누적으로 바뀔 자리다.

## 5. 자체 결정

- S-154 전환 입력·보유 폼 규칙·표시·지표 세부.

## 6. 알려진 문제와 미룬 것

- 표시 방식 세 가지의 비교, 전환 손맛, 바위 선딜 연출은 사람 확인(사용자 확인 포인트).
- 봇 전환이 잦음(지표 기록만).

## 7. 인계 사항

- **CP22를 시작하지 않고 멈춘다**(사용자 경기 구조 검토, PROGRESS "다음 할 일").
- 전환은 `FighterCombat.BeginTick`의 잡기·공격 확인 바로 앞. 보유 폼 `FighterState.OwnedForms`.
- 전환 지표는 `SwitchMetrics.Observe(이전 상태, 현재 상태, 이벤트)`.
