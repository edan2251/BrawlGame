## 1. 계획

- `FighterForm`(가위·바위·보 + 기존 테스트용 Test)을 파이터 상태에 두고, `CombatMode`를 읽던 분기(공격 시작, 대시 캔슬, 착지 경직, 몸통 공격성, 봇, 무기 그림)를 파이터 폼으로 옮긴다.
- `RuleSet`(시작 폼 + `FeatureSwitches` 가드·잡기·에너지). 기존 생성자는 레거시 규칙(가드 켬, 에너지 끔), 게임 기본은 가드·잡기 끔·에너지 켬.
- 정수 에너지(`EnergyParams`): 시작은 확인만, 소비는 폼별 한 지점(가위 `Launch`, 보·잡기 시작), 발사 시 부족 취소와 `EnergyShort` 이벤트, 행동당 한 번(`ActionPaid`). 대시 몸통 공격성 0.6 → 0.
- 시나리오 `form/guard/energy`, 입력 기록 v4(규칙 문자열), F1 폼·F4 가드+잡기·Insert 에너지, HUD 에너지 줄.
- 테스트: 에너지 기본, 가위 확인·소비, 취소·부족, 스위치, 대시 공격성, 회귀(A), 결정론(B), 성능.

## 2. 작업 기록

- 2026-11-02 시뮬레이션·게임 계층 수정, 컴파일 오류·경고 0(커밋 `60348d9`).
- 바위 폼의 공격 버튼은 CP19 전까지 아무것도 하지 않는다(확인만 통과하고 시작하지 않음).
- 빠른 묶음 1차 485/489: 실패 4 = 대시 피해 테스트(의도한 변화, S-149), HUD 하드코딩 색, 튜닝 에셋 체크섬 2(fast 에셋에 대시 0.6 저장). 고친 뒤 새 테스트 12개 포함 빠른 묶음 501/501.
- 새 테스트 한 건 실패: 에너지를 비용-1로 둔 같은 틱에 회복(+1)이 먼저 적용됨 → 테스트에 회복 지연을 걸도록 고침(구현 변경 없음).
- 사용자 테스트 운영 조정(D-048) 적용: 성능 측정 CP18-8은 CP20으로.
- 새 구조(사용자 경기 구조 검토)와 충돌하는 구현: 없음. 라운드 시작 시 폼은 `config.StartForm`으로 초기화한다(CP22 범위, 새 구조에서는 경기 끝까지 유지로 바뀔 예정).

## 5. 자체 결정

- S-149 대시 몸통 공격성 0. S-150 폼·규칙·에너지 구현 세부(수치, 기록 v4, 단축키, HUD).

## 6. 알려진 문제와 미룬 것

- CP18-8 성능은 CP20에서 기록(D-048).
- 바위 폼 공격은 CP19. 봇은 바위 폼에서 시험 공격 봇으로 동작(입력이 무시됨), CP20에서 바위 봇.
- CP16 이하 입력 기록(v3 이하)은 재생할 수 없다.

## 7. 인계 사항

- 폼은 `FighterState.Form`, 시작은 `SimConfig.StartForm`(라운드마다 `CreateFighter`에서 초기화; 세트·경기 유지 규칙은 CP22 범위이고 사용자 검토 중).
- 에너지 소비 지점: 가위 `FighterCombat.Launch`, 보 `StartAttack` 직후, 잡기 `StartGrab` 직후. 바위는 CP19의 발사 지점에서 `Spend`를 부르고, 선딜 시작에는 `CanAfford`만.
- 새 테스트용 설정은 `FormEnergyTests.FormConfig` 참고(`RuleSet` 생성자).
