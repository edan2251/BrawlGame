## 1. 계획

1. 구조물 데이터: 짝 파일 `props`에 종류(09 2절 표 7종)·크기·위치·각도·줄/축 등을 선언하고 시뮬레이션의 고정 용량 구조물 목록으로 읽는다. 지금은 모두 움직이지 않는 임시 물체(회전된 직사각형 포함)로 캐릭터와 충돌한다.
2. 경계 튕김: 경계 사각형(화면과 일치)을 시뮬레이션에 두고 03 3절 규칙(피해, 반사, 경직, 히트스탑, 면역 45틱)을 구현. 바깥 테두리 칸은 동작에서 빼고 그리지 않는다. 연출: 경고 선, 물결, 섬광, 흔들림, 전기 소리.
3. 맵 6개 다시 만들기: 밝은 고정 지형 8% 이하, 물체 면적 10~16%, 묶음 14~22개 4층 이상, 구조물 60% 이상, 중심 구조물, 모든 종류 등장, 쌓인 상자 기둥 3개 맵 이상, 매달린 블록 간격.
4. 테스트: 맵 데이터 계산(CP13-1), 경계 튕김(CP13-2), 봇 측정(CP13-3), 캡처 비교(CP13-4).

## 2. 작업 기록

- 2026-11-01 CR-002 0절: 결정 D-029~D-034, 명세 03·04·08·09, CHECKPOINTS(CP13~CP18), PROGRESS, CR-001 대체 표시, CLAUDE.md 갱신.
- 경계 튕김(시뮬레이션): 맵 머리글 `boundary: true`면 테두리 칸은 검증만 하고 지형이 아니다. 경계는 테두리 안쪽 면(36 × 20에서 ±17 × ±9, 16:9 화면 ±17.8 × ±10 안). `TerrainCollision.Move` 끝에서 경계 접촉을 기록하고 `ResolveContacts`가 03 3절 규칙을 적용(피해·반사 × 1.1·안쪽 최소 14·경직 14·히트스탑 5·면역 45틱, 면역 중 반사 × 0.5, 잡고 있거나 잡힌 동안은 멈추기만). 밀어내기·잡기·던지기 배치는 `ClampToBoundary`, 쌓기는 위 경계를 천장으로. `BoundaryHit` 이벤트. 경계에 닿으면 공중 점프·대시 회복(아래 경계에서 빠져나올 수 있게). `BoundaryTests` 26개 통과(네 변 × 속도 3 × 두 방향, 면역, 최대 속도 300회 이탈 0, 거울, SyncTest 3600틱). 처음 실패 2건은 테스트 가정(낙하 속도 상한 30, 면역 대기 중 아래 경계로 떨어짐)을 고쳐 해결.
- 구조물 데이터: `PropKind` 7종, `PropDef`(묶음, 크기, 줄 고정점·축, 이어진 부품). 짝 파일 `props`(hanging, spinner, hinged, seesaw, linked, pillar, box, `mirror`). `ArenaDef.WithProps`가 구조물마다 움직이지 않는 임시 물체 상자(`TerrainKind.Prop`, 동작은 Solid와 같음)를 붙인다. 연출 `PropView`: `prop` 색, 줄, 축 점, 상자 밝기 ±6%, 기둥 이음매.
- 맵 6개 새로(A Chimes·Scales, B Mobile·Totems, C Ruins·Gantry). 설계 도구로 원칙을 먼저 계산: 고정 지형 6.5~7.5%, 물체 12.2~14.9%, 묶음 18~21개, 구조물 묶음 61~78%, 띠 5~6개 사용, 1단계 블록 흔들림 ±30° 겹침 0, 7종 모두, 기둥 3개 맵. 첫 시도에서 시작 칸과 상자가 0.05 겹친 맵 2개(불변식 위반 1924·1540), 닿지 못한 높은 블록 4곳을 고침. CP12 맵 6개와 `showcase_cp12_*`는 지움(git 기록에 남음).
- 봇(측정 도구) 보강: 경계 튕김 맵에서 아래가 빈 곳은 가시처럼 피함, 옆 경계 앞에서 감속·대시 안 함, 충전을 뗄 때 상대 너머 3유닛(최대 12) 안에 경계가 있으면 다른 방향, 아래가 빈 단방향 발판에서 내려가지 않음.
