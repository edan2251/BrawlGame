## 1. 계획

1. 남은 디버그 단축키: F2 맵 순환, F9 입력 기록 시작·중지, F10 마지막 기록 재생, `~` 도움말(빌드에서는 처음 실행 시 열림). 튜닝 프리셋 전환 키 F11(기본 ↔ 더 빠르게).

## 6. 알려진 문제와 미룬 것

- 봇과 무작위 허수아비는 사람이 아니다. 거리 재기, 속임수, "왜 졌는지 이해" 같은 질문은 사람이 해 봐야 답이 나온다. 숫자는 방향 참고용.
- 효과음 15개는 실제로 들어 보지 못했다(사람 확인 필요).
- 개발 빌드는 처음 실행 시 Windows 방화벽 창이 뜰 수 있다(취소해도 됨). 창 제목은 `Project_Brawl`.
- 빌드에서 F9로 남긴 기록은 `Builds/Windows/Replays/`에 저장된다. 에디터 F10으로 보려면 프로젝트 루트 `Replays/`로 복사해야 한다.
- 기록 도중 튜닝 에셋을 고치면(라운드 사이 다시 읽기) 재생 결과가 달라질 수 있다(경고 로그).
- Pit에서 봇은 가시를 피하지 않아 가시 비중이 크다(fast Swing Pit 1분에 가시 57회). 사람이 해 보고 가시 데미지·면역을 볼 것.
- 붙잡은 동안 두 몸 그림 겹침, 맵별 배경 실루엣이 같음(이전 CP에서 이어짐).

## 8. 사용자 보고 요약과 추천 (Q-004 근거)

- 봇 기준 관찰
  - 모드 A가 라운드가 짧고(11~12초 대 14~15초) 지형을 훨씬 많이 쓴다(벽꽝 분당 7~12 대 1~3.6). 1번 축(탄력 있는 물리 움직임)과 2번 축(지형·위치)에 더 가깝다.
  - 모드 B는 패링이 더 자주 나오고(분당 2.0 대 0.8) 무기가 보여서 판정을 읽기 쉽다. 대신 잡기가 없으면 벽꽝이 드물다(분당 1.0).
  - 잡기는 두 모드 모두 가드를 줄이고(A 27.1 → 10.6, B 9.3 → 6.2) 클래시를 줄인다. 모드 B에서는 벽꽝을 1.0 → 3.6으로 늘려 B에 모자란 지형 사용을 채운다. 상성(공격 > 잡기 > 가드 > 공격)이 실제로 작동한다는 신호.
  - fast 프리셋은 라운드를 4~13% 줄이고, A에서는 가드가 줄고 벽꽝이 늘어난다. B에서는 변화가 작다.
- 추천(사람이 해 본 뒤 확정): **모드 A + 잡기 유지**를 1순위로. 몸이 무기라 ROUNDS류 물리감과 지형 활용이 자연스럽고, 업그레이드 카드(튕김 횟수, 위력, 크기)로 넓히기 쉽다. 플레이해서 "왜 졌는지"가 잘 안 읽히면, B의 보이는 판정(예: 내려찍기 포고)을 A의 공중 기술로 옮기는 "섞기"를 2순위로 본다.
