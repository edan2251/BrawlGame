# 체크포인트

체크포인트(CP)는 **Claude Code가 스스로 구현, 검증, 기록하는 단위**다. 사용자 승인을 기다리지 않고 순서대로 진행한다. 진행 절차는 `CLAUDE.md` 4절, 기록 형식은 `docs/progress/templates/checkpoint-log.md`.

| CP | 이름 | 핵심 산출물 |
|---|---|---|
| 15 | 구조물 물리 2단계 | 경첩, 연결 구조, 구조물끼리 충돌, 끊어짐 |
| 16 | 구조물 물리 3단계 | 쌓인 상자와 부분적으로 무너지는 기둥 |
| 17 | 준비 | 명세 10, 기준선 보존, 느린 테스트 분리 |
| 18 | M1: 파이터별 폼 기반 | 폼 상태, 에너지, 가드·잡기 스위치 |
| 19 | M1: 투사체와 바위 폼 | 투사체 풀, 속성, 바위 |
| 20 | M1 끝: 보 폼과 속성 해석기 | 3×3 상호작용, 봇 매트릭스, `M1-summary.md` |
| 21 | M2: 폼 전환 | 전환 규칙, 지표, 표시 세 가지 |
| 22 | M2: 라운드·세트·경기, 세트 패자 선택 | 상태 기계, 4.7(개정) 초기화 |
| 23 | M2: 증강 틀 | 수정자 파이프라인, 대표 증강 4개 |

## 검증 기준 읽는 법

- 기준 ID는 `CPn-번호`. 로그의 검증 표에 이 ID로 결과를 적는다.
- 종류 표시: **[T]** 자동 테스트(따로 적지 않으면 EditMode), **[M]** 측정해서 수치 기록, **[S]** 캡처를 열어 체크리스트로 확인, **[C]** 콘솔·에디터 상태 확인, **[R]** 소스 규칙 점검, **[G]** Git.
- 수치 범위는 **초기 튜닝값 기준**이다. 테스트는 가능하면 설정값에서 기대값을 계산해서 비교한다. 의도적으로 튜닝을 바꿔 범위가 달라지면 기준을 고치되, 이전 값과 이유를 로그와 `DECISIONS.md`에 남긴다.
- 테스트용 맵이 필요하면 테스트 코드 안에 문자 격자 문자열로 둔다.

## CP15. 구조물 물리 2단계

**목표**: `09-props-physics.md` 2절 표의 2단계. 맵 6개의 경첩 발판, 연결 구조, 끊어지는 줄이 움직이기 시작한다. 구조물끼리 충돌한다.

**검증 기준**
- **CP15-1 [T]** 경첩 각도 한계와 복원, 연결 구조가 3600틱 동안 폭발하거나 떨지 않음.
- **CP15-2 [T]** 구조물끼리 충돌: 겹침 기준, 마찰로 미끄러짐이 멈춤, 터널링 없음.

- **CP15-4 [T]** 결정론, SyncTest, 대칭성(맵 6개 전부).
- **CP15-5 [M]** 성능과 봇 측정 재실행, 기록.
- **CP15-6 [S]** 연결 구조가 움직이는 연속 캡처, 줄이 끊어지는 순간.

## CP18. M1: 파이터별 폼 기반

**범위**
- `CombatMode`를 읽는 곳(`FighterCombat`의 분기, `FighterMovement`의 착지 분기, 몸통 공격성 계산 등)을 **파이터별 폼 상태**로 옮긴다. 폼은 가위(돌진), 보, 바위 세 가지다(바위와 보의 실제 공격은 CP19~20에서 채운다. 이 CP에서는 폼 상태와 분기 틀을 만든다).
- 가드·잡기를 끄는 스위치. 이미 있는 `GrabEnabled`를 활용하고 가드 스위치를 더한다. 꺼진 상태에서는 해당 입력을 무시한다.
- 공격 에너지: 풀과 회복 지연 타이머를 파이터 상태에 넣고(체크섬과 `Visit` 포함), 4.4의 규칙대로 구현한다. 공격을 시작하는 곳(`StartCharge`, `StartAttack`, `StartGrab`)에서는 **확인만** 하고, **소비는 폼별 소비 시점**에서 한다(가위는 `Launch`에서 발사할 때, 보와 잡기는 시작할 때, 바위는 CP19의 발사 때). 취소와 발사 시 부족의 처리도 4.4대로 구현한다. 이동 대시의 몸통 공격성 가중치를 0으로 둔다. HUD에 작은 에너지 표시를 더한다.
- 시나리오와 `SimConfig`에서 폼과 스위치를 지정할 수 있게 한다.
- 입력 기록 형식 버전을 올린다(2절).

**검증 기준**
- **CP18-1 [T]** **(A) 기존 행동 회귀**: 폼을 가위로, 가드·잡기를 켠 설정에서 기존 시나리오와 기존 테스트가 통과한다. 의도한 변경 목록이 로그에 있다.
- **CP18-2 [T]** **(B) 새 구조의 결정론**: 3600틱 두 번 실행 체크섬 동일, 저장·복원, SyncTest, 입력 기록 재생 일치.
- **CP18-3 [T]** 에너지 기본: 회복 지연 뒤 회복하고, 바닥나면 공격 시작이 막히며(입력은 버려지고 대기하지 않는다) 이동·점프·이동 대시는 가능하다.
- **CP18-4 [T]** **가위 충전의 확인과 소비**: 에너지가 `LungeCost` 미만이면 충전이 시작되지 않는다. 충전 중 에너지는 변하지 않는다. 발사하면 에너지가 **정확히 `LungeCost`만** 줄어든다(충전을 시작할 때 차감이 없으므로 **이중 차감이 없다**). 최소 충전과 최대 충전 자동 발사에서도 같다. 연속 N회 발사의 총 소비가 N × `LungeCost`다(회복이 없는 조건).
- **CP18-5 [T]** **취소와 발사 시 부족**: 충전 중 피격, 경계 튕김, KO로 끊기면 에너지 감소가 0이다. 테스트에서 충전 중 에너지를 강제로 줄이고 놓으면 발사되지 않고 충전이 취소되며, 에너지는 그대로이고 부족 이벤트가 남는다.
- **CP18-6 [T]** 가드·잡기를 끄면 해당 입력이 무시되고, 켜면 기존과 같다.
- **CP18-7 [T]** 이동 대시의 몸통 공격성이 0이면 에너지가 0인 파이터가 대시 접촉으로 피해를 줄 수 없다.
- **CP18-8 [M]** `Step` 평균 시간, `Step` GC 0, 롤백 8틱 시간 기록(기존 예산 안).
- **CP18-9 [T]** 새 상태 필드가 모두 체크섬 범위에 들어간다(기존 범위 테스트).

## CP19. M1: 투사체와 바위 폼

**범위**
- **투사체 풀**: 파이터당 고정 용량, 시뮬레이션 상태에 포함(체크섬, 저장·복원, `StateDiff`), `Step`에서 GC 0. 풀이 찼을 때의 동작(가장 오래된 것 소멸 또는 발사 불가)은 자체 결정하고 기록한다.
- 4.3의 속성(`Reflectable`, `PierceFighter`, `PierceProp`)과 지형·경계·구조물·상자와의 기본 관계. 터널링이 없어야 한다.
- 바위 기본공격: 선딜, 발사 방향(8방향), 속도, 피격 시 피해·넉백·히트스탑(공통 틀 재사용). 에너지는 4.4대로 **동작을 시작할 때 `ShotCost` 이상인지 확인**하고 **발사할 때 한 번 소비**한다(취소, 부족 처리 포함).
- 연출: 투사체 그림(코드로 그린 도형), 발사·적중 이벤트와 효과음(합성).

**검증 기준**
- **CP19-1 [T]** 풀 한도: 한도까지 쏘고 초과해도 크래시나 상태 오염이 없고, 정한 동작대로 처리된다.
- **CP19-2 [T]** 결정론, 저장·복원, SyncTest(투사체가 날아다니는 장면 포함), 입력 기록 재생.
- **CP19-3 [T]** 터널링 없음: 최대 속도 투사체로 두께 0.5의 지형·발판·상자를 여러 각도에서 맞혀도 통과가 없다.
- **CP19-4 [T]** 지형, 경계, 구조물, 상자에 닿았을 때의 반응이 4.3대로다. 데이터로 `PierceFighter`·`PierceProp`을 켠 투사체가 각각 파이터와 구조물·상자를 통과하되 지형은 막힌다.
- **CP19-5 [T]** 바위의 에너지: `ShotCost` 미만이면 발사 동작이 시작되지 않고, 발사하면 정확히 한 번만 소비되며, 선딜 중 피격으로 끊기면 소비가 없고, 발사 틱에 부족하면 발사하지 않고 취소한다.
- **CP19-6 [T]** 대칭성(미러 시나리오).
- **CP19-7 [M]** 투사체 풀이 가득 찬 장면에서 `Step`, 롤백 8틱, GC 기록.

## CP20. M1 끝: 보 폼, 속성 해석기, 3×3 상호작용

**범위**

- **속성 해석기**: 4.1을 구현한다. 폼 쌍별 분기가 아니라 속성 비교로 처리하고, 두 파이터의 판정은 기존처럼 같은 스냅숏에서 동시에 계산하고 동시에 적용한다(번호 우선순위 없음).
- 봇(`CombatBot`)이 세 폼을 각각 쓸 수 있게 한다. 이 CP에서 봇의 폼은 시드로 고정한다. 목표는 진행 확인이지 실력이 아니다.
- **M1 봇 매트릭스**: 에너지 켬/끔 × 폼 쌍(자기 대전 포함 3×3) × 맵 6개 × 시드 6 × 2분.
- `docs/progress/M1-summary.md`: 발견한 문제, 알려진 문제, 마음에 걸리는 임시 기본값. 승률 수치는 방향 지표로 기록만 한다. 이 요약을 쓰고 **멈추지 않고 CP21로 간다.**

**검증 기준**
- **CP20-1 [T]** 상호작용 표(4.1)의 **모든 칸**(폼 쌍 + 공격하지 않는 상태 + 같은 종류끼리)을 결정적 시나리오 테스트로 확인한다. 결과의 종류(피해, 기절, 반사, 중단, 상쇄)와 대상이 표와 같다.
- **CP20-2 [T]** 보의 반사 조건: 활성 판정이 아닌 선딜·후딜에는 반사하지 않고, `Reflectable`이 거짓이면 반사하지 않고 투사체가 그대로 진행해 보를 일반 명중시키며, 반사 뒤 소유자가 바뀌고 반사된 투사체가 원래 소유자를 맞힌다. 연속 반사 상한과 한 활성 판정당 한 번 규칙이 동작한다.
- **CP20-3 [T]** 속성 구분: 관통 투사체가 파이터는 맞히고 계속 가고, 구조물·상자는 통과 여부를 따로 갖고, 관통 투사체도 보의 활성 판정에는 반사된다.
- **CP20-4 [T]** 동시 처리와 대칭성: 같은 틱에 서로의 공격이 닿아도 번호 우선순위 없이 같은 결과가 나오고, 미러 시나리오의 결과가 일치한다.
- **CP20-5 [T]** 결정론, SyncTest(세 폼이 섞인 장면), 입력 기록 재생.
- **CP20-6 [M]** 봇 매트릭스: 모든 조합에서 **불변식 위반 0**(경기장 이탈, NaN, 1초를 넘는 겹침 등), 라운드가 끝나지 않는 조합 없음. 라운드 길이 분포와 폼 쌍별 승률은 기록만 한다(합격 기준 아님). 투사체 도배로 라운드가 끝나지 않으면 붕괴로 보고 튜닝 두 번까지 시도한다.
- **CP20-7 [M]** 가드·잡기를 끈 상태의 벽꽝/분, 경계·구조물·상자 데미지 비중을 `baseline-cp16.md`와 나란히 표로 정리한다(지형 축이 얼마나 줄었는지 확인).

## CP22. M2: 라운드·세트·경기, 세트 패자 선택

**범위**
- 라운드·세트·경기 상태 기계(10 문서 3절, 4.6): 경기 시작의 비공개 동시 초기 폼 선택(한 번), 세트 3라운드 2선승, **세트가 끝나면 세트 패자만** 선택하는 단계(기존 `RoundTransition` 훅 자리), 선택지 최대 4개(이 CP에서는 **폼 획득만 동작**하고 증강 자리는 CP23이 채운다), 5세트 선승 경기 종료, 재시작.
- **초기화를 10 문서 4.7(개정)대로 구분해 구현한다.** 상태를 전투 부분과 경기 부분(폼, 증강, 라운드 점수, 세트스코어, 선택 횟수, 맵 순환)으로 나눠 비교할 수 있게 한다.
- 선택은 시뮬레이션 입력으로 흘려 보내 리플레이와 롤백에 포함한다.
- 선택 화면: 선택지는 **패자 쪽 영역에만** 보이고, 선택 결과는 표시하지 않는다(D-046). 짧은 영문과 코드로 그린 아이콘.
- 코드의 `MatchState` 이름은 그대로 두고 필드 이름으로 정리한다(자체 결정).
- 봇의 선택은 시드 무작위.

**검증 기준**
- **CP22-1 [T]** 상태 전이: 2승으로 세트 획득, 2:0, 2:1, 5세트 선승 경기 종료, 경기 종료 뒤 재시작이 정의대로 동작한다.
- **CP22-2 [T]** 라운드가 끝나도 선택이 없고, **세트 패자만** 선택한다(세트 승자는 선택이 없다). 무승부 라운드에는 점수와 선택이 없다. 경기를 끝내는 세트 뒤에는 선택이 없다.
- **CP22-3 [T]** 폼 획득이 반영돼 전환 가능한 폼 목록이 늘어난다. 이미 가진 폼은 선택지에 나오지 않는다.
- **CP22-4 [T]** **라운드 시작 초기화**: 4.7의 라운드 초기화 대상이 모두 초기 상태다(체력 최대, 시작 위치·정지, 행동 Idle과 모든 타이머 0, 에너지 최대와 지연 0, 투사체 0개, 구조물·상자가 새 맵의 초기 상태). 폼, 증강, 선택 횟수, 라운드 점수, 세트스코어, 난수 상태는 그대로다.
- **CP22-5 [T]** **잔여 상태 누수 없음**: 봇이 격하게 싸운 라운드가 끝난 직후 다음 라운드를 시작한 상태의 **전투 상태 필드**가, 같은 맵·같은 폼으로 새로 시작한 라운드의 전투 상태 필드와 일치한다. 경기 부분은 따로 4.7의 "유지" 값과 비교한다.
- **CP22-6 [T]** **라운드 시작 폼**: 세트 패자가 새 폼을 획득했으면 다음 라운드를 그 폼으로 시작하고, 아니면 직전 현재 폼으로 시작한다. 라운드 중에 전환해 둔 폼이 다음 라운드와 다음 세트로 이어진다.
- **CP22-7 [T]** **세트 종료**: 라운드 점수만 초기화되고 폼·보유 폼·선택 횟수·세트스코어·맵 순환은 유지된다. **경기 재시작**에서는 폼, 증강, 선택 횟수, 세트스코어가 초기화되고 초기 폼을 새로 고르며 맵 순환을 새로 섞는다.
- **CP22-8 [T]** **무승부 라운드**: 점수와 선택 없이 같은 라운드를 다시 하고, 라운드 시작 초기화만 적용된다.
- **CP22-9 [T]** 같은 시드면 선택지가 같다. 선택 단계를 포함한 SyncTest와 입력 기록 재생 최종 체크섬이 일치한다.
- **CP22-10 [T]** 라운드마다 맵이 교체되는 기존 순환과 호환된다.
- **CP22-11 [M]** 봇이 경기 전체(5세트 선승)를 시드 6개로 불변식 위반 0, 중단 없이 완주한다. 경기 길이와 선수당 선택 횟수(최대 4)를 기록한다.
- **CP22-12 [S]** 선택 화면과 경기 종료 화면의 렌더링 오류만 1~2장으로 확인(D-048).

## CP23. M2: 증강 틀

**범위**
- 10 문서 5.3의 수정자 파이프라인(고정 적용 순서, 충돌·우선순위, 제한적 중복), 증강 데이터 형식(`Target`, `Rarity` 분류 필드 포함, D-055), 후보 제시(시드 추첨 + 슬롯·무의미 조합·중복 상한 필터), 경기 끝까지 누적(최대 4개). CP22의 선택 단계에 증강 선택지를 연결한다.
- 5.4의 대표 증강 4개(가위 2, 바위 1, 보 1). 돌진 속도 배율은 최대 3번 중복(D-056).
- 증강이 발동하는 순간 이름 아이콘을 짧게 표시한다(평소에는 표시하지 않는다).
- 증강 상태를 시뮬레이션 상태에 포함한다(체크섬, 저장·복원, `StateDiff`).

**검증 기준**
- **CP23-1 [T]** **순서 독립성**: 증강 4개를 가능한 모든 획득 순서(4! = 24)로 부여해도 최종 속성과 수치가 같다(실제 증강과 테스트 전용 증강 모두).
- **CP23-2 [T]** **충돌·우선순위**: 플래그 반대 설정, 같은 동작 슬롯 대체, 동시 트리거를 **테스트 전용 증강 데이터로** 강제로 부여해도 5.3의 규칙대로 결정적으로 해소된다.
- **CP23-3 [T]** 트리거 연쇄 깊이 상한과 수치 하한(비용 0 이상, 선딜 1틱 이상).
- **CP23-4 [T]** **증강이 상성을 바꾼다(철갑탄 전후 검사)**: 요청서 6절 CP23-4와 같다(반사 ↔ 일반 명중, 대조군, 해석기 코드 동일).
- **CP23-5 [T]** **누적 A+B가 함께 유효**: 가위에 돌진 속도 배율과 즉발 돌진을 둘 다 붙이면 즉발, `InstantLungeSpeed` × 배율, 순서 무관, `LungeCost` 한 번. 속도 배율만 붙인 충전형은 충전 속도 × 배율.
- **CP23-6 [T]** **무의미 조합**: 테스트 전용 데이터로 필터와 휴면이 결정적이고 순서와 무관하다.
- **CP23-7 [T]** **후보 제시와 실제 선택**: 같은 시드면 후보가 같다. 가위만 가진 파이터의 첫 선택지가 정확히 4개(바위 획득, 보 획득, 가위 증강 2개). 슬롯 충돌·중복 상한 필터는 데이터로 확인한다.
- **CP23-8 [T]** **(가) 같은 폼 4중첩 안정성**: 테스트 전용 증강 데이터로 가위에 증강 4개(배율 중복 포함)를 강제로 부여한 상태에서 결정론·SyncTest가 일치하고, 가장 빠른 돌진으로 두께 0.5의 지형·발판·상자를 여러 각도에서 쳐도 몸이 통과하지 않으며, 수치 하한이 지켜진다.
- **CP23-9 [T]** **(나) 가위 전문화 경로**: 실제 증강 데이터만으로, 가위만 가진 파이터가 가위 증강만 고르는 모든 경로에서 네 번의 선택이 모두 가능하고 어느 단계에서도 후보가 0이 되지 않는다(모든 시드 결과가 같은 판정). 최종 속도 배율은 1.2³.
- **CP23-10 [T]** 결정론, SyncTest, 입력 기록 재생(증강 상태 포함), 대칭성.
- **CP23-11 [M]** 증강이 붙은 봇 경기가 불변식 위반 0으로 완주한다(성능은 CP24에서 기록, D-048).
- **CP23-12 [S]** 증강 발동 아이콘과 선택 화면의 렌더링 오류만 1~2장(D-048).

## CP24. M2 끝: 통합, 빌드, 전달 (멈춤)

**범위**
- 초기 폼 선택 → 라운드 → 세트 종료와 세트 패자 선택 → 폼·증강 누적(경기 끝까지) → 경기 종료 → 재시작의 전체 흐름을 점검한다.
- Windows 개발 빌드를 만들고 `docs/PLAYTEST.md`를 새로 쓴다: **조작법**(전환 키, 선택 키, 스위치 키), **사용자 확인 포인트**, **알려진 문제**.
- 빌드로 흐름을 직접 확인하기 어려우면, 디버그 전용으로 최소한의 자동 진행 인수(봇 대 봇)와 상태 전이 로그를 추가해도 된다.
- 성능 기록(D-048), 느린 묶음 포함 전체 테스트.
- 사용자 보고 후 **멈춘다.** M3는 시작하지 않는다.

**사용자 확인 포인트에 들어갈 것**: 전환의 느낌과 전환 지표, 세트 패자 선택의 경제(폼 획득과 증강 중 무엇을 고르게 되는가, 가위 전문화), 비공개 심리전(한 화면 한계 포함), 현재 폼 표시 세 가지 비교, 가드·잡기를 끈 느낌, 에너지 느낌, **불리한 폼으로도 대응 방법을 찾을 수 있는가**, 경기 길이, 손맛·구성·연출(D-048).

**검증 기준**
- **CP24-1 [M]** 빌드를 30초 실행한 `Player.log`에 프로젝트 쪽 오류가 없다.
