# 체크포인트

체크포인트(CP)는 **Claude Code가 스스로 구현, 검증, 기록하는 단위**다. 사용자 승인을 기다리지 않고 순서대로 진행한다. 진행 절차는 `CLAUDE.md` 4절, 기록 형식은 `docs/progress/templates/checkpoint-log.md`.

| CP | 이름 | 핵심 산출물 |
|---|---|---|
| 0 | 환경과 골격 | 패키지, 폴더, 어셈블리, Git/GitHub, MCP 동작 확인 |
| 1 | 결정론 시뮬레이션 코어 | 상태·체크섬·SyncTest·입력 기록·시나리오 실행기 |
| 2 | 이동과 지형 | 이동 명세 전체, 맵 파서, Box 맵 |
| 3 | 연출 기반 | 잉크 외곽선 아트, IK 팔다리, 몸 변형, 먼지·잔상, HUD 뼈대, 효과음 도구 |
| 4 | 전투 공통 기반 | 체력, 판정, 히트스탑, 넉백, 벽꽝, 가드·패링, 클래시, 경기 흐름, 허수아비, 타격 연출 |
| 5 | 모드 A: 돌진 충돌 | 충전 돌진, 위력 판정, 가독성 연출 |
| 6 | 모드 B: 무기 휘두르기 | 방향별 기술, 무기 IK, 포고 |
| 7 | 보조 스킬: 잡기·던지기 | 상성 행렬 완성 |
| 8 | 경기 완성도 | 맵 3종, 가시, KO 파편, 효과음 전체, HUD |
| 9 | 비교용 빌드 | Windows 빌드, 플레이테스트 안내, 사용자 보고 |
| 10 | 온라인 (초안) | 착수 전 질문 필수 |

## 검증 기준 읽는 법

- 기준 ID는 `CPn-번호`. 로그의 검증 표에 이 ID로 결과를 적는다.
- 종류 표시: **[T]** 자동 테스트(따로 적지 않으면 EditMode), **[M]** 측정해서 수치 기록, **[S]** 캡처를 열어 체크리스트로 확인, **[C]** 콘솔·에디터 상태 확인, **[R]** 소스 규칙 점검, **[G]** Git.
- 수치 범위는 **초기 튜닝값 기준**이다. 테스트는 가능하면 설정값에서 기대값을 계산해서 비교한다. 의도적으로 튜닝을 바꿔 범위가 달라지면 기준을 고치되, 이전 값과 이유를 로그와 `DECISIONS.md`에 남긴다.
- 테스트용 맵이 필요하면 테스트 코드 안에 문자 격자 문자열로 둔다.

## 모든 CP 공통 완료 조건

- **ALL-1 [C]** 컴파일 오류 0. 이 CP에서 새로 생긴 경고 0(불가피하면 사유 기록).
- **ALL-2 [T]** 지금까지의 모든 자동 테스트 통과(회귀 없음).
- **ALL-3 [R]** 시뮬레이션 규칙 점검 통과(`01-architecture.md` 8절).
- **ALL-4 [C]** 해당 CP의 showcase 시나리오를 플레이 모드에서 실행하는 동안 콘솔 오류 0.
- **ALL-5 [G]** 커밋, 태그 `cp-n`, 푸시 완료.
- **ALL-6** 로그, `PROGRESS.md`, `DECISIONS.md` 갱신 완료.

## CP0. 환경과 골격

**목표**: 이후 모든 작업이 굴러갈 바닥을 깐다. 게임 코드는 거의 없다.

**범위**
- Unity 버전, URP 2D Renderer, 사전 승인 패키지(Input System, 2D Animation, Test Framework) 확인 및 설치.
- Player Settings의 Run In Background 켜기.
- `01-architecture.md`의 폴더와 어셈블리 정의 생성. `Knockbox.Simulation`은 `noEngineReferences: true`.
- 씬 두 개: `Main`(경기), `Sandbox`(시나리오 실행과 캡처).
- 스모크 테스트 1개(EditMode).
- Git 초기화, 첫 커밋. Q-003(저장소 이름과 공개 범위)을 질문하고 답을 받으면 GitHub 저장소 생성과 푸시. 답을 기다리는 동안 CP1을 진행해도 된다(푸시만 미룸).

**검증 기준**
- **CP0-1 [C]** `ProjectSettings/ProjectVersion.txt`가 6000.3.x. 정확한 패치 번호를 로그에 기록.
- **CP0-2 [C]** 활성 렌더 파이프라인이 URP이고 렌더러가 2D Renderer.
- **CP0-3 [T]** 스모크 테스트가 MCP `run_tests`로 통과.
- **CP0-4 [T]** 시뮬레이션 어셈블리가 UnityEngine을 참조하지 않음을 테스트로 확인(어셈블리 참조 목록 검사).
- **CP0-5 [S]** MCP로 `Main` 씬 스크린샷을 `docs/progress/captures/CP0/`에 저장하고 열어서 확인.
- **CP0-6 [G]** Unity를 한 번 실행한 뒤에도 `git status`에 `Library/`, `Temp/`, `Logs/` 등이 나타나지 않음.
- **CP0-7 [C]** 설치된 패키지와 버전 목록을 로그에 기록.

## CP1. 결정론 시뮬레이션 코어

**목표**: 롤백이 가능한 시뮬레이션의 뼈대와 검증 도구를 먼저 만든다. 이후 모든 CP의 자동 검증이 이 도구 위에서 돌아간다.

**범위**
- `Vec2`, `SimMath`, `Hasher`(FNV-1a), `SimRng`, `InputFrame`과 버튼 눌림/뗌 계산.
- `SimState`, `FighterState`(위치, 속도, 행동, 행동 틱, 직전 버튼 등 뼈대), `MatchState` 뼈대.
- `SimWorld.Step`: 이 단계에서는 지형 없이 단순한 중력과 좌우 이동만(결정론 검증에 의미 있는 상태 변화를 주기 위한 임시 동작).
- `SimEventBuffer`, `SimConfig`와 튜닝 ScriptableObject 변환.
- `MatchRunner`: 고정 60틱, 프레임당 최대 4틱, 보간 비율 제공, 입력 지연 설정.
- SyncTest 실행기, 입력 기록·재생, 시나리오 JSON 로더와 공용 `expect` 테스트 러너.
- 시뮬레이션 규칙 점검(테스트 또는 `Tools/` 스크립트).

**검증 기준**
- **CP1-1 [T]** 같은 시드의 무작위 입력 3600틱을 두 번 실행해 매 틱 체크섬이 같다.
- **CP1-2 [T]** 상태 저장 → 100틱 진행 → 복원 → 같은 입력으로 재진행 시 체크섬이 같다.
- **CP1-3 [T]** SyncTest(되감기 7틱)로 3600틱 동안 불일치 0.
- **CP1-4 [T]** `Step`의 GC 할당 0(Unity Test Framework의 할당 검사 제약 사용).
- **CP1-5 [R]** 규칙 점검이 금지 문자열을 실제로 잡아내는지, 일부러 위반한 임시 파일로 한 번 확인한 뒤 지운다.
- **CP1-6 [T]** 샘플 시나리오 1개가 로드되고 `expect`가 평가된다. 일부러 틀린 `expect`는 실패로 보고된다.
- **CP1-7 [T]** 입력 기록 → 재생 → 최종 체크섬 동일.
- **CP1-8 [M]** `Step` 평균 시간과 롤백 8틱 재시뮬레이션 시간을 측정해 기록(예산: 0.25ms, 2ms).
- **CP1-9 [C]** 플레이 모드에서 `MatchRunner`를 10초 실행하면 진행된 틱 수가 600 ± 2.

## CP2. 이동과 지형

**목표**: 첫 번째 축. 공격 없이 뛰어다니기만 해도 재미있는 이동.

**범위**
- `ArenaParser`와 맵 파일 3종(Box 사용, Towers와 Pit은 파싱 검증만).
- 지형 충돌(하위 단계 분할), 단방향 발판, 튕김 패드.
- `02-movement.md` 전체: 가감속, 가변 점프, 정점 보정, 빠른 낙하, 공중 점프, 코요테, 버퍼, 벽 미끄러짐·벽 점프, 대시, 대시 점프 캔슬, 파이터끼리 밀어내기.
- 임시 그래픽: 색 사각형과 지형 상자(CP3에서 교체).
- `MovementTuning` ScriptableObject와 showcase 시나리오.

**검증 기준**
- **CP2-1 [T]** 세 맵 모두 파서 검증 통과. 합쳐진 상자 수를 로그에 기록.
- **CP2-2 [T]** 최대 점프 정점 높이 3.8~4.3, 짧은 점프 1.3~1.9.
- **CP2-3 [T]** 정지에서 최대 속도까지 5~7틱, 최대 속도에서 정지까지 7~10틱.
- **CP2-4 [T]** 코요테: 발판을 벗어난 지 5틱 뒤 점프 성공, 7틱 뒤 실패(공중 점프 0으로 둔 테스트에서).
- **CP2-5 [T]** 점프 버퍼: 착지 7틱 전에 누른 점프가 착지 틱에 실행.
- **CP2-6 [T]** 벽 미끄러짐 속도 5 이하. 벽 점프 후 7틱 동안 벽 쪽 입력 무시. 폭 2짜리 수직 통로를 벽 점프 연속으로 6 이상 오른다.
- **CP2-7 [T]** 지상 수평 대시 거리 3.0~4.0, 대시 중 중력 없음, 충전 회복 조건(착지, 벽 접촉) 동작.
- **CP2-8 [T]** 터널링 없음: 대시, 빠른 낙하, 튕김 패드 최대 속도로 두께 0.5 벽을 8방향, 시작 위치 1000가지 이상에서 들이받아도 통과 0.
- **CP2-9 [T]** 단방향 발판: 아래에서 통과, 위에서 착지, 아래 + 점프로 하강.
- **CP2-10 [T]** 튕김 패드 동작. Box 가운데 기둥을 최대 점프로 넘고 짧은 점프로는 못 넘는다.
- **CP2-11 [T]** 대칭성: P1과 P2를 바꾸고 x를 반전한 시나리오의 결과가 반전해서 일치(오차 1e-4).
- **CP2-12 [T]** 이동이 들어간 상태로 CP1의 결정론 테스트와 SyncTest 통과.
- **CP2-13 [S]** showcase 캡처(대기, 달리기, 점프 정점, 벽 미끄러짐, 대시): 임시 그래픽이지만 위치와 상태가 맞는지 확인.
- **CP2-14 [M]** `02-movement.md` 9절의 손맛 질문 네 개에 대해 수치와 캡처를 근거로 자체 평가를 적는다. 사용자의 직접 플레이 평가는 CP9에서 받는다.

## CP3. 연출 기반

**목표**: 세 번째 축의 바닥. 전투가 들어오기 전에 화면이 먼저 예뻐진다.

**범위**
- `PaletteAsset`, `SpriteFactory`(도형 스프라이트 생성), 정렬 레이어.
- 파이터: 몸, 외곽선, 평면 그림자, 눈(P1 원, P2 캡슐), 몸 변형(스프링), 기울기.
- 팔다리 2D IK: 다리 걷기·공중·벽, 팔 대기·달리기.
- 지형과 배경 그리기, 카메라 프레이밍과 레터박스, 보간 렌더링.
- 먼지, 대시 잔상, 화면 흔들림 시스템(트라우마), 흔들림 줄이기 옵션.
- HUD 뼈대: 머리 위 체력 바, 점수 칸.
- `Tools/sfx_synth.py`와 이동 효과음(점프, 착지, 대시).

**검증 기준**
- **CP3-1 [S]** showcase 캡처 세트(대기, 달리기 중간, 점프 정점, 벽 미끄러짐, 대시 잔상, 착지 찌그러짐)가 `05-presentation.md` 8절 체크리스트를 통과.
- **CP3-2 [T]** PlayMode: 두 몸의 렌더 결과 밝기 차이 0.25 이상.
- **CP3-3 [T]** PlayMode: Box 맵을 120프레임 달리는 동안 발과 지면의 오차 0.05 이하.
- **CP3-4 [S]** 1280×720과 2560×1440 캡처에서 경기장과 HUD가 깨지지 않음.
- **CP3-5 [M]** 플레이 모드 1920×1080에서 프레임 시간 기록, 60fps 유지. 연출 계층의 프레임당 GC 할당을 측정해 기록(목표 0).
- **CP3-6 [T]** 연출을 켠 경우와 끈 경우(시뮬레이션만) 같은 시나리오의 최종 체크섬이 같다.
- **CP3-7 [R]** 연출 코드에 색이 하드코딩되지 않음(`PaletteAsset`과 디버그 코드 제외).
- **CP3-8 [T]** 효과음 합성 스크립트를 다시 실행해도 같은 파일이 만들어진다(고정 시드).

## CP4. 전투 공통 기반

**목표**: 두 모드가 공유하는 전투 규칙과 타격감. 모드별 기술 없이 **테스트용 공격 정의(AttackDef 데이터)**로 검증한다.

**범위**
- 체력, 행동 상태(피격 경직, 비틀거림, 반동, 가드, 패링, KO 등), 판정 원과 몸 상자.
- 상호작용 판정 단계(동시 계산·동시 적용), 히트스탑, 넉백, 경직, 연속 명중 감쇠, 벽꽝과 튕김, 가드·패링, 클래시.
- 경기 흐름 전체(Countdown → Fighting → KO → RoundEnd → RoundTransition 훅 → MatchEnd).
- 허수아비 입력원, 판정 오버레이(F3), 디버그 단축키 중 이 CP에 해당하는 것.
- 타격 연출: 번쩍임, 떨림, 파편, 고리, 흔들림, 카메라 확대, 벽꽝 금 자국, 효과음.
- `CombatTuning` ScriptableObject.

**검증 기준**
- **CP4-1 [T]** 히트스탑 동안 양쪽 위치와 행동 타이머가 멈추고, 입력 버퍼는 유지된다.
- **CP4-2 [T]** 넉백은 속도를 대체한다. 경직 공식이 맞다. 같은 공격을 반복해도 연속 4회 이상 맞지 않는다.
- **CP4-3 [T]** 벽꽝: 법선 속도 14 이상과 미만의 분기가 벽, 바닥, 천장 모두에서 맞다.
- **CP4-4 [T]** 패링 구간이 정확히 6틱, 재사용 제한 24틱, 가드 감쇠 수치가 맞다.
- **CP4-5 [T]** 동시 KO는 무승부(점수 변화 없음), 5점 선취 시 MatchEnd, 라운드 사이에 RoundTransition 이벤트 발행.
- **CP4-6 [T]** 대칭성: 공격과 피격이 들어간 미러 시나리오 결과 일치.
- **CP4-7 [T]** 전투가 들어간 상태로 SyncTest 통과.
- **CP4-8 [S]** showcase: 명중 순간(히트스탑 중), 벽꽝, 패링, 클래시, KO 직후.

## CP5. 모드 A: 돌진 충돌

**목표**: "더 빠르게 부딪힌 쪽이 이긴다"가 운이 아니라 실력으로 읽히게 만든다.

**검증 기준**
- **CP5-1 [T]** 충전 비율에 따라 발사 속도가 18~34로 선형. 4틱 미만 최소 돌진, 최대 충전 후 24틱 자동 발사.
- **CP5-2 [T]** 위력 계산: 둘 다 6 미만이면 밀어내기, 둘 다 6 이상이고 차이 4 미만이면 클래시, 그 외 높은 쪽 승리.
- **CP5-3 [T]** 데미지 4~24 범위, 넉백 방향 혼합 공식, 승자의 반동.
- **CP5-4 [T]** 지형에 부딪힌 돌진은 최대 2회 튕기고, 속도 12 미만 또는 30틱에 끝난다.
- **CP5-5 [T]** 돌진 대 패링: 반사와 비틀거림. 돌진 대 가드: 가드 규칙.
