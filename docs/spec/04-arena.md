# 04. 경기장

## 1. 원칙

- 경기장은 **한 화면에 전부 보이는** 가로 32 × 세로 18 유닛의 고정 공간이다. 카메라는 움직이지 않는다(연출용 흔들림과 짧은 확대만 허용).
- 지형은 위치 싸움을 만들기 위해 존재한다. 모든 맵은 벽, 발판, 구석 중 적어도 두 가지를 승부에 쓰이게 해야 한다.
- 경기장은 항상 벽으로 닫혀 있다. 떨어져 죽는 구멍은 없고, 대신 가시 같은 위험 지형이 있다.

## 2. 데이터 형식

맵은 사람이 읽고 고치기 쉬운 **문자 격자 텍스트**로 만든다. 파일은 `Assets/_Project/Data/Arenas/*.txt`.

```
name: Box
---
(32글자 × 18줄 격자)
```

| 문자 | 의미 | 칸 안에서 차지하는 부분 |
|---|---|---|
| `#` | 단단한 지형 | 칸 전체 (1 × 1) |
| `=` | 단방향 발판 | 칸의 위쪽 절반 (두께 0.5) |
| `B` | 튕김 패드 | 칸의 아래쪽 절반 |
| `^` | 가시(위험 지형) | 칸의 아래쪽 절반 |
| `1`, `2` | P1, P2 시작 위치 | 칸의 중심. 그 칸은 빈칸으로 취급 |
| `.` | 빈칸 | |

- 좌표계: 경기장 중심이 원점, x는 -16~16, y는 -9~9, 위쪽이 +y. 격자의 (열 c, 행 r) 칸은 `minX = c - 16`, `maxY = 9 - r`.
- 파서(`ArenaParser`)는 순수 C#이며 시뮬레이션 어셈블리에 둔다. 같은 종류의 인접한 칸을 탐욕적으로 합쳐 상자 목록으로 만든다(가로로 먼저 합치고, 같은 폭의 행끼리 세로로 합친다).
- 파서는 다음을 검증하고 실패하면 오류를 낸다: 32 × 18 크기, 테두리가 모두 `#`, 시작 위치가 각각 정확히 하나, 알 수 없는 문자 없음.
- 연출(`ArenaView`)은 같은 상자 목록으로 그림을 만든다. 시뮬레이션과 연출의 지형이 어긋날 수 없게 하기 위해서다.

## 3. 지형 종류의 동작

| 종류 | 동작 |
|---|---|
| 단단한 지형 | 모든 방향에서 막는다. 벽 미끄러짐, 벽 점프, 벽꽝의 대상 |
| 단방향 발판 | 위에서만 착지, 아래 + 점프로 통과(`02-movement.md`) |
| 튕김 패드 | 윗면에 닿으면 vy = 30. 공중 점프·대시 회복. 경직 중에 닿아도 튕긴다 |
| 가시 | 닿으면 데미지 15, vy = 20으로 튕겨 올림, 경직 20틱, 45틱 동안 가시 면역, 공중 점프·대시 회복(빠져나올 기회를 준다) |

## 4. 맵 3종

### Pit: 위험 지형 맵 (CP8)

양쪽 높은 대지 사이에 가시 구덩이가 있다. 던지기와 넉백으로 상대를 구덩이에 넣는 위치 싸움을 시험한다. 구덩이 가운데 발판과 벽 점프로 빠져나올 수 있다.

## 5. 맵 검증 기준

- 세 맵 모두 파서 검증을 통과한다.
- 모든 맵에서 두 시작 위치 모두, 이동만으로 맵의 모든 발판에 도달할 수 있다. 수동 확인 대신 시나리오나 도달 가능성 테스트로 확인하는 방법은 자체 결정한다.
- Box의 가운데 기둥은 최대 점프로 넘을 수 있고, 짧은 점프로는 넘을 수 없다.
- Towers의 튕김 패드로 가운데 방에 들어갈 수 있다.
- Pit에서 가시에 떨어진 뒤 조작만으로 대지 위로 돌아올 수 있다.
