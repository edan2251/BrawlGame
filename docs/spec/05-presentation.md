# 05. 연출 (화면, 팔다리, 타격감, 소리)

> **CR-001(2026-10-31)로 일부 대체.** 1절(아트 디렉션, 색 토큰, 렌더링 방식의 블룸 금지·레터박스), 4절의 연출 **색**, 6절(HUD)은 `08-visual-direction.md`가 대체한다(D-020, D-021). 2절 팔다리, 3절 몸 변형, 4절 타격 연출의 구조와 타이밍, 5절 연출 전용 물리, 7절 소리, 8절 체크리스트의 흑백 구분·외곽선·팔다리 항목은 그대로 유효하다. 캐릭터의 잉크 외곽선은 유지하고 지형 외곽선과 화면 테두리 띠는 없앤다.

첫 프로토타입부터 보기 좋아야 한다. 단, 연출은 시뮬레이션 결과를 **보여주기만** 하고 결과를 바꾸지 않는다.

## 1. 아트 디렉션: "잉크 외곽선 장난감 블록"

플랫한 무광 색면, 모든 캐릭터와 지형을 감싸는 **일정한 두께의 진한 잉크 외곽선**, 흐림 없이 오른쪽 아래로 살짝 밀린 **평면 그림자**. 책상 위의 장난감 블록이 싸우는 느낌이다. 이 프로젝트의 시각적 개성은 외곽선과 평면 그림자, 그리고 타격 순간의 연출 한 곳에 집중하고, 배경과 UI는 조용하게 둔다.

ROUNDS와 Square Brawl의 캐릭터, UI, 카드, 로고를 따라 하지 않는다. 두 게임의 대표 색 조합도 피한다.

### 색 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `ink` | `#24283B` | 외곽선, 지형 몸체, 팔다리 |
| `terrainLip` | `#3B4466` | 단단한 지형 윗면의 띠(두께 0.15) |
| `bgBase` | `#C9DCEB` | 배경 바탕 |
| `bgShape` | `#B3CBDF` | 배경의 큰 도형 실루엣 |
| `shadow` | `#9FB8CF` | 평면 그림자(오프셋 0.08, -0.08) |
| `p1Body` / `p1Shade` | `#FFB627` / `#E08E0B` | P1 해바라기색 |
| `p2Body` / `p2Shade` | `#7C5CFF` / `#5A3BDB` | P2 보라색 |
| `oneWay` | `#6B7AA6` | 단방향 발판 |
| `bouncy` | `#22C3A6` | 튕김 패드 |
| `hazard` | `#F0475C` | 가시, 위험 상태 외곽선 |
| `flash` | `#FFFFFF` | 피격 번쩍임 |
| `spark` | `#FFF3B0` | 클래시 불꽃 |

노랑과 보라는 색각 이상에서도 구분이 잘 되는 축이고, 흑백으로 바꿔도 밝기 차이가 크다. 토큰 값은 대비와 조화를 위해 자체 결정으로 조정할 수 있지만, 두 플레이어가 흑백에서 구분되는 조건은 지켜야 한다. 토큰은 ScriptableObject 하나(`PaletteAsset`)에 모아 코드에서 직접 색을 쓰지 않는다.

### 형태

- 몸: 1 × 1 사각형, 모서리 반경 0.12, 외곽선 0.06.
- 얼굴: 눈만 있다. P1은 둥근 점 두 개, P2는 가로로 긴 캡슐 두 개. 색만이 아니라 **모양으로도** 두 캐릭터를 구분하기 위해서다. 눈은 이동 방향이나 상대를 바라보고, 가끔 깜박이고, 피격 시 찡그리고(납작한 선), 충전 중에는 가늘어진다.
- 지형: `ink` 색 몸체에 윗면 띠, 외곽선 없이 평면 그림자만. 단방향 발판은 얇고 밝은 판, 튕김 패드는 반원 돌기 줄무늬, 가시는 삼각형 반복.
- 배경: 단색 바탕 위에 큰 사각형과 원 몇 개의 실루엣. 움직이지 않는다.

### 렌더링 방식

- URP 2D Renderer, SpriteRenderer. 스프라이트는 에디터 스크립트(`SpriteFactory`)가 코드로 생성한다(둥근 사각형 9-슬라이스, 원, 캡슐, 삼각형, 고리). 외부 이미지 에셋을 쓰지 않는다.
- 외곽선은 조금 더 큰 `ink` 스프라이트를 뒤에 겹치는 방식으로 시작한다. 셰이더 방식으로 바꾸는 것은 자체 결정.
- 블룸 같은 후처리는 쓰지 않는다. 플랫한 화면을 유지한다.
- 정렬 레이어(뒤→앞): `Background`, `Shadow`, `Terrain`, `LimbBack`, `Fighter`, `LimbFront`, `Weapon`, `Fx`, `UI`.
- 카메라: 직교, 크기 9(세로 18 유닛), 경기장을 정확히 담는다. 16:9가 아니면 `bgBase` 색으로 레터박스.

## 2. 팔다리 (2D IK)

ROUNDS처럼 몸통에 짧은 팔다리가 붙어 절차적으로 움직인다. 2D Animation 패키지의 `IKManager2D`와 `LimbSolver2D`를 쓰고, 목표점(target)을 코드로 움직인다.

| 부위 | 구성 | 동작 |
|---|---|---|
| 다리 2개 | 2마디(각 0.3), 굵기 0.12, 둥근 발 | 지상: 발을 지면에 고정하고 이상 위치에서 0.35 이상 벗어나면 5프레임 동안 0.15 높이 호를 그리며 한 발씩 내딛는다. 공중: 몸 쪽으로 접고 속도 반대로 끌린다. 벽 미끄러짐: 발을 벽에 댄다 |
| 팔 2개 | 2마디(각 0.28), 굵기 0.11, 둥근 손 | 대기: 살짝 흔들림. 달리기: 다리와 반대로 흔들림. 모드별 동작은 아래 |

- 발 위치는 시뮬레이션의 지형 상자 데이터로 직접 계산한다(연출용 레이캐스트를 따로 구현, Unity 물리 불필요). 발이 지면을 뚫거나 뜨는 오차는 0.05 이하.
- 모드 A(돌진): 충전 중 팔을 뒤로 젖힌다. 돌진 중에는 진행 방향으로 팔을 뻗는다.
- 모드 B(휘두르기): 앞쪽 손이 무기를 쥔다. 시뮬레이션의 공격 단계(시작, 활성, 후딜)에 맞춰 손 목표점이 뒤로 젖혔다가, 호를 따라 휘두르고, 끝까지 따라간다. 무기 끝의 궤적이 시뮬레이션 판정 원과 시각적으로 일치해야 한다(디버그 오버레이로 확인).
- 잡기: 두 팔을 잡기 상자 쪽으로 뻗고, 붙잡는 동안 손이 상대 몸에 붙는다. 던질 때 크게 휘두른다.
- 가드: 두 팔을 몸 앞에 교차한다.
- 2D IK 설정이 이 구조에 맞지 않거나 문제가 생기면 해석적 2마디 IK를 직접 구현해도 된다. 바꿨다면 자체 결정으로 기록한다.

## 3. 몸의 변형과 회전

- 스프링-댐퍼로 비율(scale)을 움직인다. 착지: 가로 1.3 × 세로 0.7에서 약 8프레임 동안 튕기며 복원. 점프: 세로로 늘어남. 이동 속도에 따라 진행 방향으로 최대 1.25 늘어남.
- 충전: 납작해지며 떨린다. 충전 단계에 따라 외곽선이 밝아진다.
- 이동 중 기울기 최대 8°. 피격 경직 중에는 속도에 비례해 **굴러가듯 회전**한다(맞았다는 것이 한눈에 보이게).

## 4. 타격 연출

타격감은 여러 연출을 **같은 순간에 겹쳐서** 만든다. 시뮬레이션의 히트스탑이 시간을 멈추고, 연출이 그 멈춘 순간을 채운다.

| 이벤트 | 연출 |
|---|---|
| 명중 | 양쪽 흰색 번쩍임(맞은 쪽 4프레임, 때린 쪽 3프레임), 히트스탑 동안 맞은 쪽 떨림(데미지 비례), 공격자 색의 삼각 파편 6~10개, 흰 고리 확산(0.2초), 화면 흔들림(데미지 비례), 15 이상이면 카메라 확대 1.5% 6프레임, 효과음 |
| 클래시 | 접점에 `spark` 색 별 모양 폭발과 불꽃, 양쪽 외곽선 번쩍임, 중간 흔들림, 금속성 효과음 |
| 패링 | 패링한 쪽 색의 고리 폭발, 짧은 화면 색 반전 느낌(2프레임), 높은 "팅" 소리 |
| 벽꽝 | 부딪힌 지형에 잉크색 금 간 자국(1.5초 동안 사라짐), 먼지 폭발, 강한 흔들림, 카메라 확대, 묵직한 충돌음, 작은 지형 파편(연출 물리) |
| 착지·점프 | 먼지 원 2~4개, 몸 변형 |
| 대시 | 몸 색 잔상 3개(투명도 40%에서 사라짐), 바람 소리 |
| 돌진 | 공격성 위력에 비례하는 잔상 길이, 위력 6 이상이면 `hazard` 색 외곽선 |
| 잡기·던지기 | 손이 붙는 순간 짧은 번쩍임, 던져진 쪽에 잔상 |
| KO | 히트스탑 20 뒤 진 쪽 몸이 4~6조각으로 깨져 **Unity 2D 물리로** 경기장을 튕겨 다닌다, 큰 폭발, 이긴 쪽이 통통 튀며 기뻐함 |

- 화면 흔들림은 "트라우마" 방식(누적값의 제곱에 비례, 시간에 따라 감소), 최대 진폭 0.35 유닛.
- **흔들림 줄이기 옵션**(F7): 흔들림 30%, 화면 전체 번쩍임과 색 반전 끔.
- 연출용 난수는 `UnityEngine.Random`을 써도 된다(시뮬레이션과 무관).

## 5. 연출 전용 물리

KO 파편, 벽꽝 파편 같은 연출에만 Unity 2D 물리를 쓴다. 지형 상자 데이터로 연출용 `BoxCollider2D`를 만들고, 연출 물리 전용 레이어끼리만 충돌하게 한다. PhysicsExamples2D(6000.3 브랜치)의 래그돌, 파편화 예제를 참고한다. 처음에는 표준 `Rigidbody2D` 컴포넌트로 만들고, 저수준 물리 API로 바꾸는 것은 성능이나 표현상 이유가 있을 때 자체 결정한다.

## 6. HUD

- 각 파이터 머리 위에 작은 체력 바(폭 1.2, 높이 0.12). 줄어든 부분은 흰색으로 0.4초 남았다가 줄어든다.
- 화면 위 가운데에 라운드 점수 표시(양쪽 5칸).
- 라운드 시작 카운트다운과 KO 문구는 크고 짧게. 프로토타입에서는 영문 짧은 단어와 숫자만 써서 한글 폰트가 필요 없게 한다(한글 폰트 도입은 Q-002).
- 화면 왼쪽 아래에 현재 모드와 맵 이름을 작게 표시(디버그 단계에서만).

## 7. 소리

- 효과음은 외부 파일 없이 `Tools/sfx_synth.py`(파이썬 표준 라이브러리만 사용)로 합성해 `Assets/_Project/Audio/Sfx/`에 WAV로 만든다. 다시 생성할 수 있게 스크립트와 파라미터를 커밋한다.
- 목록: 점프, 착지, 대시, 약한 명중, 강한 명중, 클래시, 패링, 가드, 벽꽝, 잡기, 던지기, 가시, 튕김 패드, 카운트다운, KO.
- 재생 시 음높이 ±5% 무작위. 같은 효과음이 한 프레임에 겹치면 하나만 재생.

## 8. 시각 검증 체크리스트 (캡처를 열어 확인)

- 두 캐릭터를 흑백으로 바꿔도 구분된다. PlayMode 테스트나 에디터 스크립트에서 렌더 결과의 두 몸 중심 픽셀 밝기(상대 휘도) 차이가 0.25 이상인지 수치로 확인한다. 추가 파이썬 패키지는 쓰지 않는다.
- 외곽선이 끊기거나 겹쳐서 두꺼워진 곳이 없다.
- 팔다리가 몸에서 떨어져 보이지 않고, 발이 지면을 뚫거나 뜨지 않는다.
- 지형, 캐릭터, 배경이 서로 묻히지 않는다.
- 1280×720과 2560×1440에서 레이아웃과 HUD가 깨지지 않는다.
- 이전 체크포인트의 같은 장면 캡처와 비교해 의도하지 않은 변화가 없다.
