# 07. 온라인 대전 (초안)

> 이 문서는 방향을 기록한 초안이다. **CP16(CR-001로 CP10에서 번호 이동)은 착수 전에 반드시 사용자에게 질문한다**(`DECISIONS.md` Q-005). 그 전까지는 이 문서를 근거로 코드를 만들지 않는다. 다만 CP1~CP9의 구조가 이 방향을 막지 않는지는 계속 확인한다.

## 목표

1대1 온라인 대전에서 로컬 대전과 거의 같은 손맛을 낸다. 근접 대전은 몇 틱 차이로 승부가 갈리므로, 입력을 기다리는 방식(lockstep)보다 **롤백 넷코드**가 기본 방향이다.

## 롤백의 개요

1. 상대 입력이 아직 오지 않은 틱은 "직전 입력과 같다"고 예측해서 진행한다.
2. 실제 입력이 도착했는데 예측과 다르면, 그 틱의 저장 상태로 되감고 실제 입력으로 현재 틱까지 다시 시뮬레이션한다.
3. 체감 지연을 줄이려고 소량의 입력 지연(예: 2틱)을 함께 쓴다.

이를 위해 이미 지켜온 조건: 결정론적 시뮬레이션, 상태 복제·복원, 체크섬, SyncTest, 입력 기록.

## 착수 전에 정해야 할 것 (질문 목록)

- 배포 플랫폼과 매칭 방식: Steam, 친구 초대 코드, 공개 매칭 등
- 연결 방식: P2P 직접 연결, 릴레이 서버 경유
- 사용할 기술: GGPO 계열의 C# 롤백 라이브러리, Photon Quantum 같은 결정론 엔진(유료이며 시뮬레이션을 그 구조로 다시 써야 함), 직접 구현 + 전송 계층 중 무엇으로 할지. 각 후보의 현재 상태와 라이선스는 착수 시점에 다시 조사한다.
  - **첫 검토 후보: Backdash**(C# 롤백 넷코드, MIT, 2026-10 기준 활발히 관리됨, D-027). 결정은 여전히 Q-005다.
- 숫자 표현: float 유지 또는 고정소수점 전환(D-004). 서로 다른 PC와 빌드 사이의 일치 여부를 실제로 측정한 뒤 판단한다. 구조물 물리(D-025)가 들어오면 float 연산량이 늘어나므로 함께 측정한다.
- 비용: 서버나 릴레이 사용료가 드는지

## 설계 메모

- 최대 되감기 8틱, 입력 지연 2틱을 출발점으로 한다.
- 30틱마다 체크섬을 교환해 불일치(desync)를 감지하고, 감지 시 양쪽 입력 기록을 저장한다.
- 연출 이벤트는 예측 상태에서 먼저 재생하고, 되감기로 사라진 이벤트는 조용히 정리한다. 이미 재생한 효과음과 파티클을 어떻게 다룰지는 이벤트 식별자 `(틱, 종류, 파이터)`로 처리한다.
- 관전, 재접속, 랭크 매칭은 범위 밖이다.
