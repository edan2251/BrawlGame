# 09. 인터랙티브 구조물 물리

## 1. 목표

Rounds처럼 줄에 매달려 흔들리고, 경첩으로 기울고, 맞으면 밀리는 구조물을 만든다. 근접 게임에서 구조물은 **무기**다. 돌진으로 매달린 블록을 쳐서 상대를 맞히고, 흔들리는 발판 위에서 균형을 잃고, 상대를 구조물 쪽으로 던진다.

구조물은 게임 결과에 영향을 주므로 **시뮬레이션 어셈블리 안에서 직접 만든 결정론 물리**로 구현한다(D-003 확장). 온라인 롤백을 위해 상태 저장·복원, 체크섬, SyncTest가 구조물까지 포함해야 한다. Unity 물리는 지금처럼 연출 전용이다.

Rounds 캡처에서 확인한 구조물은 대부분 **줄에 매달린 블록, 기우는 긴 발판, 여러 블록이 연결된 틀**이다. 상자가 수십 개 쌓이는 장면은 확인되지 않았다. 그래서 범용 물리 엔진이 아니라 이 종류에 맞춘 작은 물리로 충분하다.

## 2. 단계

| 단계 | CP | 내용 |
|---|---|---|
| 1 | CP13 | 회전하는 직사각형 강체. 고정점에 줄로 매달린 블록, 가운데 축에 고정돼 도는 블록. 구조물과 지형, 구조물과 캐릭터의 충돌 |
| 2 | CP14 | 경첩(각도 한계 포함)으로 기우는 발판과 시소, 여러 블록이 줄·경첩으로 연결된 구조, 구조물끼리의 충돌, 세게 맞으면 끊어지는 줄과 경첩, 연출된 쓰러짐 |
| 3 | 나중 | 자유롭게 쌓이고 무너지는 상자 더미, 고정 지형 파괴. 필요해지면 7절의 재평가부터 |

**연출된 쓰러짐**: 기둥 같은 구조물이 기준 이상의 충격을 받으면, 진짜 물리 대신 밑동을 축으로 정해진 각속도 곡선을 따라 넘어가고 정해진 각도에서 멈춘다. 넘어가는 동안의 충돌과 피해는 일반 구조물처럼 처리한다. 결정론을 지키며 무너지는 느낌을 내기 위한 방식이다.

## 3. 결정론 규칙

`01-architecture.md` 4절의 규칙을 모두 지킨다. 구조물 때문에 생기는 추가 규칙:

- **회전은 (cos, sin) 쌍으로 저장**하고, 각속도로 돌린 뒤 정규화하는 방식으로 적분한다. 삼각함수를 쓰지 않는다. Box2D v3가 같은 방식을 쓴다.
- 맵 데이터의 초기 각도를 (cos, sin)으로 바꿀 때도 시뮬레이션 안에서 `Math.Sin` 등을 쓰지 않는다. 데이터에 단위 벡터로 적거나, `SimMath`에 결정론적 다항식 근사를 둔다(Box2D v3의 cos/sin 근사를 MIT 라이선스 출처 표기와 함께 옮겨도 된다).
- 구조물 상태는 **고정 용량**(예: 강체 48, 연결 48)을 미리 할당한다. 지금의 `SimState`는 배열 없는 값 구조체라 대입이 곧 스냅숏인데, 구조물 때문에 이 성질이 깨지면 명시적 복사(`CopyTo`)와 미리 할당한 스냅숏 버퍼로 대신한다. 어느 쪽이든 체크섬(`Visit`)과 `StateDiff`에 모든 필드가 들어가야 하고, `Step`과 스냅숏 복사에 GC 할당이 없어야 한다.
- 접촉과 연결은 정해진 순서(강체 번호, 쌍 번호 순)로 생성하고 푼다. 반복 횟수는 고정한다.
- 잠들기(sleep)를 쓴다면 잠든 상태도 상태에 포함하고 결정론적으로 판정한다. 쓰지 않아도 된다.

## 4. 캐릭터와의 상호작용

캐릭터는 지금처럼 직접 만든 이동 컨트롤러로 남는다(CP2의 손맛을 지키기 위해). 캐릭터와 구조물은 아래 규칙으로 서로 영향을 준다. 한 틱 안의 처리 순서(구조물 적분과 캐릭터 이동, 충돌 해소, 상호작용 판정의 순서)는 자체 결정하되, **문서로 고정하고 대칭성 테스트로 확인**한다.

| 상황 | 규칙 (초기값) |
|---|---|
| 캐릭터 질량 | 1.0. 구조물 질량은 면적 × 밀도(기본 밀도 1, 1×1 블록 = 1.0) |
| 구조물 위에 서기 | 접촉 법선이 위쪽에서 50° 이내면 접지. 접촉점의 구조물 표면 속도를 이어받는다(같이 흔들림). 캐릭터 무게만큼 구조물을 누른다(밟으면 기운다) |
| 옆으로 밀기 | 질량 비에 따라 운동량을 주고받는다. 반발 계수 0.15 |
| 돌진이 구조물을 침 | 공격성 위력 × 1.0을 충격량으로 구조물에 준다. 캐릭터는 질량 비에 따라 튕긴다(무거운 구조물이면 지형처럼 × 0.6 반사, 가벼우면 계속 나아감) |
| 날아가는 캐릭터가 구조물에 부딪힘 | 운동량 교환. 질량 4 이상인 구조물은 벽꽝 대상(기준 속도는 지형과 같음) |
| 구조물이 캐릭터를 침 | 접촉점 상대 법선 속도 10 이상이고 캐릭터가 그 구조물 위에 서 있지 않을 때: 데미지 `clamp(round(속도 × 질량 × 0.15), 3, 18)`, 넉백 `max(10, 속도 × 0.8)`, 피격 경직은 공통 규칙. 같은 구조물-캐릭터 쌍은 20틱에 한 번 |
| 가드와 패링 | 구조물에 맞아도 가드 규칙이 적용된다. 패링 구간이면 구조물 속도를 접촉 법선 기준으로 반사 × 0.8 |
| 잡기 | 1단계에서는 구조물을 잡을 수 없다. 던져진 캐릭터는 구조물과 정상적으로 충돌한다 |
| 히트스탑 | 캐릭터가 히트스탑 중이어도 구조물은 계속 움직인다(초기 결정). 화면에서 어색하면 자체 결정으로 바꾸고 기록 |
| 마지막 접촉자 | 구조물마다 마지막으로 친 파이터를 기록한다(나중의 카드 시스템과 통계용) |

## 5. 데이터 형식

맵 형식 v2의 짝 파일에 구조물 목록을 둔다(필드 이름과 파일 형식은 자체 결정). 담아야 할 정보:

- 강체: 번호, 크기(가로, 세로), 위치, 초기 각도, 밀도 또는 질량, 선형·각 감쇠, 마찰.
- 줄: 고정점(월드 좌표) 또는 다른 강체의 국소 좌표, 강체 쪽 국소 좌표, 최대 길이, 끊어지는 충격(없으면 안 끊어짐).
- 경첩(2단계): 축 위치, 각도 한계, 끊어지는 충격.
- 연출된 쓰러짐(2단계): 밑동 축, 넘어지는 조건(충격 크기), 각속도 곡선, 멈추는 각도.

## 6. 연출

- 구조물은 테마의 `prop` 색 단색(08 문서). 줄은 같은 색의 가는 선. Shadow Caster 2D가 구조물을 따라 움직인다.
- 보간: 캐릭터와 같은 방식으로 직전·현재 상태 사이를 보간하되, 회전은 (cos, sin)을 보간 후 정규화.
- 구조물이 지형이나 캐릭터를 세게 칠 때 작은 먼지와 둔탁한 소리, 줄이 끊어질 때 짧은 소리. 효과음은 기존처럼 합성.

## 7. 오픈소스와의 관계, 재평가 조건

2026-10-31 기준 조사 결과:

| 후보 | 상태 |
|---|---|
| Box2D v3.2 (C, MIT) | 2026-10-18 출시. 서로 다른 플랫폼 사이 결정론을 공식 지원하고, 롤백용 스냅숏 API(`b2World_GetSnapshot`, `b2World_RestoreFromSnapshot`)가 있다. 단, 스냅숏은 문서에 "실험적"으로 표시 |
| Box2D.NET (C# 이식, MIT) | 활발히 관리됨. Box2D 3.1 기반이라 스냅숏이 없어 지금은 롤백 불가 |
| Unity 내장 2D 저수준 물리 | 시뮬레이션 어셈블리에서 참조 불가 |

지금은 직접 만들고, Box2D v3의 소스를 **알고리즘 참고서**로 쓴다(회전 적분, 직사각형 충돌의 접촉점 계산, 서브스텝과 부드러운 제약 같은 해법). 코드를 옮긴 부분은 파일 머리에 출처와 MIT 라이선스를 적는다.

다음 중 하나라도 생기면 멈추고 사용자에게 Box2D 도입 검토를 포함한 선택지를 묻는다.

- 2단계의 안정성 기준(8절)을 설계 변경 두 번 뒤에도 못 맞춘다.
- 상자 더미처럼 강체 수십 개가 쌓이는 표현이 필요해진다.
- 구조물 때문에 롤백 8틱 시간이 예산(2ms)을 넘는다.

## 8. 안정성과 성능 기준

| 항목 | 기준 |
|---|---|
| 에너지 | 외부 입력 없이 3600틱 동안 계 전체 운동 에너지가 처음 값을 넘지 않는다 |
| 겹침 | 해소 후 남는 겹침 깊이 0.05 이하 |
| 줄 길이 오차 | 최대 길이 대비 2% 이하 |
| 떨림 | 가만히 둔 구조물이 1초 뒤 눈에 띄게 떨지 않는다(각속도 절댓값 기준, 자체 결정) |
| 이상값 | NaN, 무한대 0 |
| `Step` | 구조물 30개에서 에디터 평균 0.25ms 이하, GC 할당 0 |
| 롤백 8틱 | 2ms 이하 |
