# 06. 경기 흐름, 입력, 디버그 도구, 시나리오

## 1. 경기 흐름

경기 흐름도 롤백 대상이므로 **시뮬레이션의 `MatchState`** 안에 있다.

### 1.1 라운드·세트·경기 (CR-003, CP22부터)

용어는 10 문서 3절: **라운드**(한 번 싸워 승패), **세트**(5라운드 중 3선승, `RoundsPerSet=5`, `RoundsToWinSet=3`), **세트스코어**, **경기**(기본 2세트 선승, `SetsToWinMatch=2`). 화면 문구는 짧은 영문(D-016).

```
경기 시작(시드, 맵 순환 섞기)
 └▶ 세트 시작: 양쪽 초기 폼 비공개 동시 선택
     └▶ 라운드 시작 초기화 ─▶ Countdown ─▶ Fighting ─▶ KO
          ├─ 무승부(동시 KO): 점수·선택 없음, 같은 라운드 다시(5라운드에 세지 않음)
          ├─ 세트 미종료: 패자만 선택(폼 획득 또는 증강, 최대 4개) ─▶ 라운드 시작 초기화
          └─ 세트 종료(3승): 세트스코어 +1
               ├─ 경기 미종료: 세트 종료 초기화(폼·증강·점수·선택 횟수) ─▶ 세트 시작
               └─ 경기 종료(2세트) ─▶ 재시작(세트스코어·맵 순환 초기화)
```

- 라운드 시작 초기화와 세트 종료 초기화의 대상은 10 문서 4.7 표가 정한다. 같은 세트 안에서는 **보유 폼, 현재 폼, 증강이 유지**되고, 전투 상태(체력, 위치, 행동, 타이머, 에너지, 투사체, 구조물)는 매 라운드 새로 시작한다.
- 선택은 시뮬레이션 입력으로 흘려 리플레이와 롤백에 포함한다. 선택지는 패자 쪽 화면 영역에만 보이고 결과는 표시하지 않는다(D-046의 한 화면 한계).
- 맵은 라운드마다 바뀌고(기존 순환), 세트가 바뀌어도 순환을 이어간다. 난수는 경기 시작 때만 시드한다.
- 아래 1.0의 흐름은 CR-003 전의 것으로, `RoundTransition` 훅이 패자 선택 단계가 된다.

### 1.0 기존 라운드 흐름 (CP4~CP16)

```
Countdown(90틱) ─▶ Fighting ─▶ KO(60틱) ─▶ RoundEnd ─┬─▶ RoundTransition(훅) ─▶ 리셋 ─▶ Countdown
                                                      └─▶ MatchEnd (아무 버튼으로 새 경기)
```

- Countdown: 파이터는 시작 위치에 고정, 행동 불가. 연출은 앞 60틱 "READY", 뒤 30틱 "GO".
- KO: 두 파이터 모두 정지. 연출이 파편과 승리 동작을 보여준다.
- 승리 조건: 먼저 5라운드(설정 가능). 무승부 라운드는 점수 없음.
- **RoundTransition**: 지금은 아무것도 하지 않고 바로 넘어가는 훅이다. 나중에 진 쪽이 업그레이드 카드를 고르는 단계가 여기 들어간다. 이벤트 `RoundTransition`을 발행하고, 다음 라운드의 설정을 바꿀 수 있는 지점이 있다는 것만 구조로 보장한다.
- 리셋: 위치, 체력, 상태 초기화. 튜닝 ScriptableObject를 다시 읽어 `SimConfig`를 갱신한다.

## 2. 입력 배치

Input System의 입력 액션 에셋 하나에 두 키보드 배치와 게임패드 배치를 둔다. 아날로그 입력은 데드존 0.35로 8방향 양자화해서 시뮬레이션에 넘긴다.

| 동작 | 키보드 왼쪽 (P1 기본) | 키보드 오른쪽 (넘패드 필요) | 게임패드 |
|---|---|---|---|
| 이동·조준 | W A S D | 방향키 | 왼쪽 스틱, 방향 패드 |
| 점프 | Space | Numpad 0 | A (South) |
| 공격 | F | Numpad 1 | X (West) |
| 대시 | Left Shift | Numpad 2 | B (East), RT |
| 가드 | E | Numpad 3 | LB, LT |
| 잡기 | Q | Numpad 4 | Y (North) |

- 키보드 왼쪽은 한 손(왼손)으로 모두 닿는 배치다. 키보드 오른쪽은 왼손으로 방향키, 오른손으로 넘패드를 쓴다.
- 시작 시 P1은 키보드 왼쪽, P2는 연결된 첫 게임패드, 없으면 키보드 오른쪽.
- 점프는 위 방향과 분리돼 있다. 위 방향은 조준(위 휘두르기, 8방향 대시·돌진·던지기)에 쓴다.

## 3. 허수아비 (테스트 상대)

AI 대신 정해진 행동을 반복하는 입력원(`IInputSource`)을 둔다. 대기, 제자리 점프 반복, 가드 유지, 40틱마다 공격, 좌우 왕복, 고정 시드 무작위. 디버그 키로 바꿀 수 있다.

## 4. 디버그 단축키 (에디터와 개발 빌드에서만)

| 키 | 동작 |
|---|---|
| F1 | 시작 폼 순환(가위 → 바위 → 보, 에디터는 시험 공격 폼 포함), 라운드 리셋 (CP18)|
| F2 | 맵: 순환(라운드마다 교체, 기본) → 맵 하나에 고정 → … (CP12, 04-arena.md 6절) |
| F3 | 판정 오버레이: 몸 상자, 공격 판정 원, 잡기 상자, 속도 벡터, 돌진 위력, 상태 이름, 틱 번호 |
| F4 | 가드·잡기 켜기/끄기(한 스위치, D-043) (CP18) |
| Insert | 공격 에너지 켜기/끄기 (CP18) |
| F5 | 라운드 리셋(튜닝 재적용) |
| F6 | P2 입력원 순환: 키보드 오른쪽 → 게임패드 → 허수아비 |
| `[` `]` | 허수아비 행동 바꾸기 |
| F7 | 흔들림 줄이기 |
| F8 | SyncTest 켜기/끄기. 불일치 시 화면 경고와 로그 |
| F9 / F10 | 입력 기록 시작·중지 / 마지막 기록 재생 |
| P / O | 일시정지 / 정지 중 한 틱 진행 |
| `~` | 단축키 도움말 표시 |

입력 기록은 프로젝트 루트의 `Replays/`에 저장한다(Git 제외). 회귀 테스트로 남길 가치가 있는 기록은 `Assets/_Project/Data/Scenarios/replays/`로 옮겨 커밋한다.

## 5. 시나리오

시나리오는 사람이 쓰는 짧은 입력 스크립트다. **자동 테스트, 화면 캡처, 버그 재현**이 모두 같은 형식을 쓴다. 파일은 `Assets/_Project/Data/Scenarios/*.json`.

```json
{
  "name": "box_full_jump",
  "arena": "Box",
  "mode": "Swing",
  "grab": true,
  "ticks": 120,
  "spawn": { "p1": [-6, -7.5], "p2": [6, -7.5] },
  "p1": [
    { "from": 0, "to": 9, "hold": ["Right"] },
    { "at": 20, "press": ["Jump"], "holdFor": 30 }
  ],
  "p2": [],
  "captures": [ { "tick": 41, "name": "apex" } ],
  "expect": [
    { "tick": 41, "fighter": 0, "field": "pos.y", "min": -3.9, "max": -3.2 }
  ]
}
```

CR-003(CP18)부터 `"form": "Scissors" | "Rock" | "Paper"`를 쓰면 폼 규칙이 된다. 이때 `"guard"`(기본 false), `"grab"`(기본 false), `"energy"`(기본 true)로 스위치를 정한다. `"form"`이 없으면 `"mode"`·`"grab"`의 레거시 규칙(가드 켬, 에너지 끔)이다.

- 입력 항목: `from`~`to` 동안 `hold`를 누르고 있음, 또는 `at` 틱에 `press`를 `holdFor` 틱(기본 1) 동안 누름. 방향은 `Left`, `Right`, `Up`, `Down`, 버튼은 `Jump`, `Attack`, `Dash`, `Guard`, `Grab`.
- `spawn`은 선택. 없으면 맵의 시작 위치. 시나리오는 Countdown을 건너뛰고 Fighting 상태에서 시작한다.
- `expect`는 선택. 지원하는 필드(`pos.x`, `pos.y`, `vel.x`, `vel.y`, `hp`, `action`, `grounded` 등)는 코드에 목록으로 둔다. 공용 EditMode 테스트 하나가 `expect`가 있는 모든 시나리오를 실행한다.
- `captures`는 플레이 모드의 `ScenarioRunner`가 그 틱이 화면에 그려진 직후 PNG로 저장한다. 저장 위치는 `Captures/<라벨>/`(프로젝트 루트, Git 제외)이며, 라벨은 실행 시 지정한다(기본: 현재 CP).
- 에디터 메뉴 `Knockbox/Run Scenario Captures`는 지정한 시나리오 목록을 플레이 모드에서 차례로 실행하고 캡처한다. Claude Code는 MCP로 이 메뉴를 실행해 시각 검증을 한다.

### 보여주기용 시나리오 (showcase)

각 CP는 자신의 시각 검증에 쓰는 시나리오를 `showcase_` 접두사로 만든다. 같은 시나리오를 이후 CP에서도 다시 캡처해 회귀를 비교한다.

## 6. 빌드
