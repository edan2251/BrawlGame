# KNOCKBOX 비교 플레이테스트 안내 (CP9)

이 빌드의 목적은 **전투 방향을 고르는 것**이다. 같은 이동·맵·연출 위에서 모드 A(돌진 충돌)와 모드 B(무기 휘두르기)를, 잡기(보조 스킬)를 켜고 끄며 비교한다. 다 해 본 뒤 마지막 절의 질문(Q-004)에 답해 주면 그 방향으로 다음 단계를 진행한다.

## 1. 실행

| 방법 | 절차 |
|---|---|
| 빌드(추천) | `Builds\Windows\Knockbox.exe` 실행. 처음에는 전체 화면이고, `Alt+Enter`로 창 모드 전환, `Alt+F4`로 종료 |
| 창 크기 지정 | 명령 프롬프트에서 `Knockbox.exe -screen-fullscreen 0 -screen-width 1600 -screen-height 900` |
| 에디터 | `Assets/_Project/Scenes/Main.unity`를 열고 Play |
| 빌드 다시 만들기 | Unity 메뉴 `Knockbox/Build/Windows Development` (약 2분, `Builds/`는 Git 제외) |

- 처음 실행하면 Windows 방화벽이 `knockbox.exe`의 네트워크 접근을 물을 수 있다. 개발 빌드가 Unity 프로파일러 연결용 포트를 열기 때문이다. 게임은 네트워크를 쓰지 않으므로 **취소**해도 된다.
- 빌드는 처음 켤 때 단축키 도움말이 열려 있다. `~`(숫자 1 왼쪽 키)로 닫고 연다. 에디터에서는 닫힌 채 시작한다.
- (CP10부터 빌드에서는 F12를 눌러야 보인다) 화면 왼쪽 위는 틱·경기 단계·라운드, 왼쪽 아래는 **지금 설정**(맵 / 모드 / 잡기 끔 표시 / 튜닝 프리셋 / P2 입력원, 기록 중이면 `REC`, 재생 중이면 `REPLAY`)이다. 비교할 때는 아래 줄을 보고 설정을 확인한다.
- 경기는 5라운드 선승. 경기가 끝나면 아무 버튼으로 새 경기.

## 2. 조작

| 동작 | P1 키보드 왼쪽 | P2 키보드 오른쪽(넘패드 필요) | 게임패드 |
|---|---|---|---|
| 이동·조준 | W A S D | 방향키 | 왼쪽 스틱, 방향 패드 |
| 점프 | Space | Numpad 0 | A |
| 공격 | F | Numpad 1 | X |
| 대시 | Left Shift | Numpad 2 | B, RT |
| 가드 | E | Numpad 3 | LB, LT |
| 잡기 | Q | Numpad 4 | Y |

- P2는 게임패드가 연결돼 있으면 게임패드, 없으면 키보드 오른쪽이다. 혼자 해 볼 때는 `F6`을 눌러 P2를 **봇**(아래 줄 `P2 bot`)으로 바꾼다. 봇은 지금 모드에 맞게 싸운다(모드 A는 거리를 보고 충전해서 돌진, 모드 B는 위·아래 휘두르기도 씀, 잡기가 켜져 있으면 잡고 던짐, Pit에서는 가시를 피함). 정해진 행동만 반복하는 허수아비는 `F6`으로 한 칸 앞에 있고 `[` `]`로 행동(대기, 점프 반복, 가드 유지, 40틱마다 공격, 좌우 왕복, 무작위)을 고른다.
- 점프는 위 방향과 따로 있다. 위 방향은 조준(위 휘두르기, 8방향 대시·돌진·던지기)에 쓴다.

### 모드별 공격 버튼

| | 모드 A: 돌진 충돌 | 모드 B: 무기 휘두르기 |
|---|---|---|
| 공격 | **누르고 있으면 충전, 떼면** 방향키 방향(8방향, 중립이면 앞)으로 돌진. 오래 충전할수록 빠름 | 중립·좌우: 앞 휘두르기, 위: 위 휘두르기, 공중에서 아래: 내려찍기(맞히면 위로 튕겨 오름) |
| 승패 | 몸끼리 부딪히면 **더 빠르게 부딪힌 쪽**이 이긴다. 비슷하면 클래시 | 무기 판정이 닿으면 명중. 서로의 무기가 겹치면 클래시 |
| 대시 | 약한 공격 판정이 있다 | 이동 전용. 대시 시작 4틱 뒤부터 공격으로 캔슬 |

### 공통

- **가드**: 누른 순간 6틱은 패링(상대 공격을 튕겨 내고 반격 기회), 그 뒤 누르고 있는 동안 가드.
- **잡기**: 몸 앞의 상대를 붙잡는다. 잡기 버튼을 **떼는 순간**(또는 20틱 뒤) 그 순간의 방향으로 던진다. 뒤로도 던질 수 있다. 벽에 던지면 벽꽝.
- 상성: 공격은 잡기를 이기고, 잡기는 가드를 이기고, 가드(패링)는 공격을 이긴다. 같은 행동끼리는 클래시.
- 세게 날아가 벽·천장에 부딪히면 **벽꽝**(추가 데미지). 가시(Pit 맵 바닥)는 데미지와 함께 튕겨 올린다.

## 3. 디버그 단축키

| 키 | 동작 |
|---|---|
| F1 | 전투 모드 전환(A 돌진 ↔ B 휘두르기, B는 동결), 새 경기. 테스트 공격 모드는 에디터에서만 |
| F2 | 맵 순환(Box → Towers → Pit), 새 경기 |
| F3 | 판정 오버레이(몸 상자, 공격 판정 원, 잡기 상자, 속도, 돌진 위력) |
| F4 | 잡기 켜기/끄기, 새 경기 |
| F5 | 새 경기(튜닝 다시 읽음) |
| F6 | P2 입력원 순환: 키보드 오른쪽 → 게임패드 → 허수아비 → 봇 |
| `[` `]` | 허수아비 행동 바꾸기 |
| F7 | 화면 흔들림 줄이기 |
| F8 | SyncTest(롤백 검사) 켜기/끄기 |
| F9 | 입력 기록 시작(새 경기로 시작) / 멈추고 저장 |
| F10 | 마지막 기록을 처음부터 재생 |
| F11 | 튜닝 프리셋 순환(default ↔ fast), 새 경기 |
| P / O | 일시정지 / 멈춘 동안 한 틱 진행 |
| F12 | 디버그 글자(상태, 틱, 설정 줄) 켜기/끄기. 빌드에서는 꺼진 채 시작(CP10) |
| `~` | 도움말 |

### 튜닝 프리셋 (F11)

`default`는 명세의 초기값, `fast`는 같은 규칙을 더 빠르게 만든 값이다. 데미지·넉백·체력은 같다.

| 항목 | default | fast |
|---|---|---|
| A 최대 충전 / 최대 충전 유지 | 36틱 / 24틱 | 24틱 / 18틱 |
| A 돌진 속도 / 최대 지속 | 18→34 / 30틱 | 22→38 / 24틱 |
| A 같은 두 몸의 충돌 판정 간격 | 10틱 | 8틱 |
| B 앞 휘두르기(시작/활성/후딜) | 5/4/14 | 4/3/11 |
| B 위 휘두르기 | 5/4/16 | 4/3/12 |
| B 내려찍기 | 6/5/16 | 5/4/12 |
| B 대시 캔슬 가능 시점 | 4틱 | 3틱 |
| 공통 클래시 반동 / 가드 경직 / 패링당한 경직 | 12 / 10 / 28틱 | 10 / 8 / 24틱 |
| 헛잡기 후딜 | 22틱 | 18틱 |

## 4. 추천 비교 순서

한 조합에 5~10분, 가능하면 두 사람이 한다. 각 조합에서 세 맵(F2)을 한 번씩 돌고, 마음에 드는 조합은 F11로 `fast`도 해 본다.

| 순서 | 설정(아래 줄 표시) | 바꾸는 법 | 집중해서 볼 것 |
|---|---|---|---|
| 1 | `mode Charge (no grab)` | F1로 Charge, F4로 잡기 끔 | 돌진 타이밍 싸움, 충전 중 읽기 |
| 2 | `mode Charge` | F4로 잡기 켬 | 잡기가 충전·가드 심리를 어떻게 바꾸는지 |
| 3 | `mode Swing (no grab)` | F1로 Swing, F4로 잡기 끔 | 거리 재기, 휘두르기 방향 선택 |
| 4 | `mode Swing` | F4로 잡기 켬 | 잡기가 가드를 얼마나 무너뜨리는지 |

## 5. 질문지 (조합마다 짧게)

조합마다 아래 다섯 가지에 1~5점과 한 줄 메모면 충분하다(`spec/03-combat.md` 7절).

1. **눈치 싸움 시간**: 거리를 재다가 아무도 안 들어가는 시간이 얼마나 되는가? (지루할 만큼 길다 1 ↔ 적당하다 5)
2. **패배 이해**: 진 쪽이 "왜 졌는지" 바로 이해하는가? (모르겠다 1 ↔ 바로 안다 5)
3. **지형 활용**: 벽과 발판이 실제 승부에 쓰이는가? (거의 안 쓰임 1 ↔ 승부를 가름 5)
4. **잡기와 가드**: 잡기가 있을 때와 없을 때 가드의 쓰임이 어떻게 달라지는가? (잡기 켬 조합에서만, 메모로)
5. **확장 여지**: 이 모드가 업그레이드 카드(예: 돌진 튕김 추가, 무기 길이 증가)로 넓힐 여지가 큰가? (작다 1 ↔ 크다 5)

전체를 마친 뒤 하나 더:

6. 손맛(히트스탑, 흔들림, 번쩍임, 효과음)이 지나치거나 모자란 곳이 있었나? `default`와 `fast` 중 어느 쪽 속도가 맞았나?

## 6. 봇 영상으로 먼저 보기

혼자서는 두 사람 싸움을 보기 어려우므로, 봇끼리 싸운 1라운드 영상을 비교 순서대로 만들어 두었다.

- 위치: `Recordings\bot_rounds\` (Git 제외). 목록과 라운드별 수치는 `Recordings\bot_rounds\index.md`.
- 16개: 비교 4조합 × 맵 3개(기본 속도) `01`~`12`, 4조합 Box `fast` `13`~`16`. 1920×1080 60fps, 효과음 포함, 한 편 15~31초.
- 조합마다 봇 경기 20판 중 라운드 길이가 **중간인 판**이다(좋은 장면만 고르지 않음).
- 각 영상 옆 `.kbrp`를 프로젝트 루트 `Replays\`에 복사하면 게임에서 F10으로 같은 판을 볼 수 있다. `_mid.png`·`_ko.png`는 라운드 중간과 KO 장면.
- 다시 만들기: Unity 메뉴 `Knockbox/Record/Bot Round Videos`(약 7분, Unity 창이 앞에 있어야 함).
- 봇은 사람처럼 거리를 재거나 속이지 않는다. 영상으로 규칙과 손맛을 보고, 눈치 싸움은 F6 봇 상대나 두 사람으로 확인한다.

## 7. 문제 장면 남기기 (F9 입력 기록)

1. 문제가 나올 것 같은 설정(모드, 잡기, 맵, 프리셋)을 먼저 고른다.
2. **F9**: 새 경기가 시작되며 기록이 시작된다(아래 줄에 `REC`).
3. 문제 장면이 나오면 다시 **F9**: 기록이 멈추고 파일로 저장된다(`REC`가 사라짐).
   - 빌드: `Builds\Windows\Replays\날짜_시각.kbrp`
   - 에디터: 프로젝트 루트의 `Replays\날짜_시각.kbrp`
4. **F10**으로 바로 다시 볼 수 있다. 기록은 입력만 저장하므로, 같은 결과가 나오면 화면 아래에 `REPLAY`가 뜨고 로그에 "최종 체크섬이 기록과 같음"이 남는다. 끝나면 F5로 평소 경기로 돌아간다.
5. 전달할 때는 `.kbrp` 파일을 프로젝트 루트의 `Replays\`에 복사하고, 파일 이름과 **몇 초쯤에 무엇이 이상했는지** 한 줄을 남겨 준다. 그대로 재현해서 고친 뒤, 가치 있는 기록은 회귀 테스트(`Assets/_Project/Data/Scenarios/replays/`)로 남긴다.

빌드의 로그는 `%USERPROFILE%\AppData\LocalLow\DefaultCompany\Project_Brawl\Player.log`에 있다.

## 8. 마지막 질문 (Q-004)

다 해 본 뒤 하나를 골라 주면 된다. 섞기나 다른 방식이면 한두 줄 설명을 붙여 준다.

- **모드 A**(돌진 충돌)로 간다
- **모드 B**(무기 휘두르기)로 간다
- **섞는다**(예: 기본은 B, 대시나 특수기로 A의 돌진)
- **둘 다 버리고** 다른 방식
- 그리고 **잡기**를 유지할지(유지 / 빼기 / 카드로만)
