## 0. 진행 방식

### 0.1 멈추는 곳은 한 곳

CP17부터 CP24까지 **승인을 기다리지 않고 이어서 구현, 검증, 기록한다.** 사용자 확인 지점은 **CP24 끝** 하나뿐이다. M1(CP20 끝)에서도 사용자의 플레이 확인을 기다리지 않는다. M1은 자체 검증 결과를 `docs/progress/M1-summary.md`에 남기고 바로 M2로 간다.

### 0.2 세션 운영

- CP마다 사용자가 새 세션을 열어 재개하는 것을 기본 절차로 삼지 않는다. 한 세션에서 지원되는 범위까지 이어서 진행한다.
- 세션은 사용 한도나 컨텍스트 한계로 언제든 끊길 수 있다. 끊겨도 **한 줄로 이어갈 수 있게** 다음을 지킨다.
  - 의미 있는 단위마다 커밋한다. 컴파일되지 않는 상태로 오래 두지 않는다.
  - CP 안에서도 큰 단계(예: 투사체 풀 완료, 속성 해석기 완료)가 끝날 때마다 `PROGRESS.md`의 "지금"과 "다음 할 일"을 갱신한다.
  - `PROGRESS.md` 맨 위에 **재개 방법 한 줄**("PROGRESS.md 보고 이어서 진행해줘")을 항상 적어 둔다.
- 컨텍스트를 줄이는 기능(요약, 압축 등)이 지원되면 쓰고, 정리 뒤에는 `PROGRESS.md`의 인계 기록으로 이어간다.
- **사용자의 조치가 반드시 필요한 경우**는 아래뿐이다. 이런 상황이 되면 `PROGRESS.md` 맨 위 재개 방법을 갱신하고 대화에서 바로 알린다.
  1. 사용 한도 소진 뒤 재개
  2. Unity 에디터가 닫히거나 MCP 연결이 끊김
  3. 모델 변경이 필요하다고 판단될 때(기본은 지금 모델로 계속한다)
  4. 컨텍스트 한계로 도구가 스스로 정리하지 못할 때
- `CLAUDE.md` 12절 1항("체크포인트마다 새 세션으로 시작한다고 가정한다")은 "세션이 새로 시작될 수 있으므로 시작 시 읽는 범위를 지킨다. CP 경계에서 멈추지 않는다"로 고친다. 나머지 절약 규칙은 그대로 유지한다.

### 0.3 질문 정책 (`CLAUDE.md` 7절에 더해)

**멈추고 묻는 경우**
- 컴파일·테스트 오류가 두 번 시도 뒤에도 풀리지 않을 때
- 결정론이나 롤백(SyncTest)이 설계 변경 두 번 뒤에도 깨질 때
- 4절의 임시 기본값에 없고 게임 경험을 크게 바꾸는 규칙이 필요할 때
- **새 빌드에 레거시 전투 전체를 유지해야 한다고 판단될 때.** 이유와 비용을 먼저 설명하고 사용자 결정을 받는다
- `CLAUDE.md`에 정해둔 권한이 필요한 경우와 파괴적 작업

**묻지 않고 기록만 하는 경우**
- 수치, 승률, 세부 밸런스, 4절의 임시 기본값 해석, 구현 방법, 테스트 방법

**M1의 구분**
- **미뤄도 되는 것**: 폼 간 승률과 세부 밸런스 조정, 위력 가독성 정교화. 기록만 하고 넘어간다.
- **해결하고 넘어갈 것**: 합의한 공격 충돌 규칙(4절)이 틀리게 동작하는 문제, 진행이 깨지는 문제(라운드가 끝나지 않음, 경기장 이탈, NaN, 결정론 불일치). 이런 붕괴는 같은 문제당 튜닝 두 번까지 시도하고, 그래도 안 되면 질문한다.

## 2. 기준선 보존과 회귀 검사

### 보존

- 소스는 태그 `cp-16`으로 이미 보존돼 있다. 삭제하지 않는다.
- `Builds/Windows`(CP16 빌드)를 `Builds/Baseline_CP16`으로 복사한다. 폴더가 없으면 새로 만들지 말고 사용자에게 알린다.
- 현재 수치를 `docs/progress/baseline-cp16.md`에 남긴다. 기존 봇 측정 도구로 다시 측정할 수 있는 것은 재측정한다: 라운드 평균 길이, 벽꽝/분, 경계·구조물·상자·가시 데미지 비중, 클래시/분. 맵 6개, 모드 A + 가드·잡기 켬 기준.
- **새 빌드에 레거시 전투 전체(모드 A/B + 가드 + 잡기)를 유지하는 것은 기본 범위에서 제외한다.** 전역 `CombatMode` 경로를 계속 살려둬야 해서 비용이 크다. 꼭 필요하다고 판단되면 이유와 비용을 먼저 설명하고 결정을 받는다.
- 가드, 잡기, 모드 B의 **코드는 지우지 않는다.** 스위치로 비활성화하거나 보로 재사용한다.

### 체크섬 정책

상태 구조가 바뀌면 CP16과 체크섬 숫자가 같아야 한다고 강제하지 않는다. 대신 두 검사를 구분해서 기록한다.

| 구분 | 무엇을 검사하나 | 방법 |
|---|---|---|
| **(A) 기존 행동 회귀** | 이동, 지형, 구조물 물리, 경계 튕김, 가위 돌진의 핵심 행동, 넉백 같은 기존 결과가 의미상 그대로인가 | 체크섬이 아니라 **의미 있는 값**(위치, 속도, 체력, 이벤트 순서)으로 비교한다. 폼을 가위로 두고 가드·잡기 스위치를 켠 설정에서 기존 시나리오의 `expect`와 기존 테스트가 통과해야 한다 |
| **(B) 새 구조의 결정론과 재생** | 새 상태 구조 안에서 같은 입력이 같은 결과를 내는가 | 3600틱 두 번 실행 체크섬 동일, 저장·복원, SyncTest, 입력 기록 재생 최종 체크섬 일치 |

- 의도한 변화로 기대값이 달라진 테스트는 근거와 함께 고치고 S 결정에 기록한다. 의도하지 않은 변화는 회귀로 보고 고친다.

## 4. 임시 기본값 (시험용, 확정 아님)

수치는 데이터(튜닝 값)로 두고 하드코딩하지 않는다. 런타임 스위치는 5절의 세 가지만 만든다.

### 4.1 공격 속성과 상호작용

공격에 **속성**을 붙이고, 충돌이 일어나면 속성을 비교해 결과를 정한다. 폼 쌍마다 따로 규칙표를 만들지 않는다. 이 구조가 있어야 증강이 속성을 바꿔 상성을 뒤집을 수 있다. 속성 이름은 자체 결정한다.

| 충돌 | 임시 결과 |
|---|---|
| 투사체 → 돌진 중인 파이터 | 돌진이 끊기고 **짧은 기절**, 피해 |
| 보의 근접 **활성 판정** → 투사체 | **반사**(아래 규칙) |
| 돌진 → 보의 근접 활성 판정 | 돌진 위력이 기존 임계(6) 이상이면 돌진이 이긴다. 보의 공격이 **중단**되고 피해를 받으며 돌진은 계속된다. 임계 미만이면 돌진은 공격성이 없는 것으로 보고 보의 판정이 그대로 맞는다 |
| 가위끼리 | 기존 위력 비교(클래시 포함) 유지 |
| 보끼리 | 클래시 |
| 투사체끼리 | 서로 소멸 |
| 투사체 → 돌진·활성 판정이 아닌 파이터 | 일반 명중(피해, 넉백, 히트스탑은 공통 틀) |
| 공격하지 않는 상태의 대상 | 모든 공격이 일반 명중 |

### 4.2 보의 반사

- **폼 자체가 항상 반사하는 것이 아니다.** 보가 근접공격을 낼 때 **활성 판정(활성 틱의 판정 원)** 이 투사체와 겹치는 틱에만 반사한다. 선딜이나 후딜 중에는 반사하지 않는다.
- 반사는 투사체의 `Reflectable`이 참일 때만 일어난다. `Reflectable`이 거짓인 투사체는 근접 활성 판정과 겹쳐도 **영향을 받지 않고 그대로 진행한다**(소멸하지도 반사되지도 않는다). 진행 경로에서 보의 몸에 닿으면 일반 명중이다.
- 반사되면 소유자가 반사한 파이터로 바뀌고, 진행 방향이 반대가 되며, 반사한 파이터에게 에너지 비용은 없다. 반사된 투사체는 원래 소유자를 맞힐 수 있다.
- 한 번의 활성 판정은 같은 투사체를 한 번만 반사한다. 핑퐁을 막으려고 한 투사체의 연속 반사에 상한(임시 3)을 둔다.
- 반사 판정과 보의 파이터 적중 판정은 같은 활성 판정 안에서 독립적으로 처리한다.

### 4.3 투사체의 속성 구분

투사체에는 **반사 가능 여부**와 **관통 대상**이 각각 따로 있는 속성이다.

| 속성 | 기본값 | 의미 |
|---|---|---|
| `Reflectable` | 참 | 보의 활성 판정에 반사된다 |
| `PierceFighter` | 거짓 | 참이면 파이터를 맞힌 뒤 소멸하지 않고 계속 간다(같은 대상은 한 번만 맞힌다) |
| `PierceProp` | 거짓 | 참이면 구조물·상자를 통과한다 |
| 지형·경계 | 항상 막힘 | M2에서는 지형을 통과하는 속성을 만들지 않는다 |

기본 투사체는 지형, 경계, 구조물, 상자에 닿으면 소멸한다(구조물에 충격량을 전달하지 않는다). 세 속성은 모두 데이터로 켜고 끌 수 있고, CP19~CP20의 테스트가 데이터로 직접 검증한다. **관통은 M2의 대표 증강에 포함하지 않는다(M3 후보).** 관통 투사체도 `Reflectable`이 참이면 보의 활성 판정에 반사되므로, 관통은 그 자체로 보에 대한 상성을 바꾸지 않는다. 상성을 바꾸는 대표 증강은 `Reflectable`을 바꾸는 5.4의 철갑탄이다.

### 4.4 공격 에너지

| 항목 | 임시 기본값 |
|---|---|
| 풀 | 파이터당 하나, 모든 폼이 공유 |
| 규모 | 연속 공격 3~4번에 바닥나고, 마지막 공격이 끝난 뒤 약 1초 지나서 회복이 시작되며, 완전 회복에 약 3초 |
| 비용 | 폼마다 다르게 데이터로 둔다(`LungeCost`, `ShotCost`, `SwingCost`, 잡기를 켠 경우 `GrabCost`) |
| 바닥났을 때 | 확인에서 막혀 **공격이 시작되지 않는다.** 입력은 버려지고 대기하지 않는다. 이동, 점프, 이동 대시는 계속 가능하다 |
| **이동 대시의 몸통 공격성** | **끈다**(가중치 0, 튜닝 값). 에너지 없이 피해를 주는 구멍을 막는다 |
| 반사 | 비용 없음 |

**확인과 소비의 시점** (폼 데이터로 지정한다)

| 행동 | 확인(시작할 때, 차감 없음) | 소비(한 번) |
|---|---|---|
| 가위 충전 | 에너지가 `LungeCost` 이상이어야 충전을 시작한다 | **발사할 때** `LungeCost` |
| 가위 즉발 돌진(5.4 증강) | 누른 틱에 `LungeCost` 이상 | 같은 틱(시작 = 발사) |
| 바위 | 에너지가 `ShotCost` 이상이어야 발사 동작을 시작한다 | **발사할 때** `ShotCost` |
| 보 | `SwingCost` 이상 | 공격을 **시작할 때** |
| 잡기(스위치를 켠 경우) | `GrabCost` 이상 | 시작할 때 |

**규칙**
1. **소비는 행동당 정확히 한 번이다.** 확인 단계에서는 차감하지 않으므로 충전 시작과 발사에서 **이중으로 차감되지 않는다.** 소비 지점은 폼별로 한 곳이며, 새 행동이 시작될 때 그 행동의 소비 기록을 새로 한다.
2. 충전·발사 동작 중에는 에너지가 변하지 않는다(행동은 배타적이고 피격은 에너지를 깎지 않는다). 회복 지연 타이머는 공격 행동(충전, 돌진, 선딜, 활성, 후딜) 동안 리셋돼 회복하지 않고, 행동이 끝난 때부터 센다.
3. **취소**: 충전이나 선딜이 발사 전에 끊기면(피격 경직, 경계 튕김, KO, 라운드 종료·초기화) **소비하지 않는다.**
4. **발사 시 부족**: 발사 틱에 에너지가 비용보다 적으면(정상 흐름에서는 확인 규칙 때문에 생기지 않지만, 이후 규칙이나 증강이 에너지를 줄이는 경우에 대비한다) **발사하지 않고 행동을 취소하며 소비하지 않는다.** 부족으로 취소됐다는 사실은 이벤트로 남긴다.
5. 최소 충전(짧게 놓아도 최소 돌진)과 최대 충전 유지 뒤 자동 발사도 같은 비용을 한 번 소비한다. 충전 비율은 비용에 영향을 주지 않는다.

### 4.5 폼 전환

| 항목 | 임시 기본값 |
|---|---|
| 전환 입력을 받는 때 | 자유 상태(지금 공격을 시작할 수 있는 상태)에서만. 공격 중, 후딜, 경직 중의 전환 입력은 무시한다 |
| 전환 시간 | 즉시. 새 폼의 선딜이 전환의 비용이다 |
| 히트스탑 중 눌린 전환 | 히트스탑이 끝난 뒤 처리한다(공격 입력과 같은 방식) |
| 폼별 상태(재장전 등) | 파이터 상태에 폼 번호로 보관하며, **전환해도** 초기화되지 않는다(라운드 시작 때는 초기화, 4.7) |
| 에너지 | 전환해도 변하지 않는다 |
| 추가 제한(전환 쿨타임, 무방비 시간 등) | **넣지 않는다.** 5.2절의 지표로 문제가 확인될 때만, 이유를 적고 비교해서 도입을 제안한다 |

### 4.6 세트, 선택, 경기

| 항목 | 임시 기본값 |
|---|---|
| 초기 폼 | 세트 시작마다 둘 다 비공개로 동시에 하나를 고른다 |
| 라운드 종료 후 | **패자만** 선택한다. 무승부 라운드(동시 KO)는 점수와 선택이 모두 없고, **세트 안의 5라운드에 세지 않고 같은 라운드를 다시 한다.** 기존 코드의 처리와 다르면 자체 결정으로 맞추고 기록한다 |
| 선택지 | 최대 4개. 미보유 폼 획득, 보유 폼의 증강 후보(시드로 추첨) |
| 선택 횟수 | 세트 구조상 한 선수가 얻는 선택은 최대 2번이다(세 번 지면 세트가 끝난다) |
| 초기화 | 라운드 시작과 세트 종료의 초기화 대상은 **4.7**로 구분한다 |
| 맵 | 라운드마다 교체(기존 순환 유지) |
| 봇의 선택 | 시드 기반 무작위 |
| 선택 입력 | 시뮬레이션 입력으로 흘려 리플레이와 롤백에 포함한다. 선택 단계에서는 기존 버튼 비트를 선택 번호로 해석해도 된다(입력 비트는 5개 쓰이고 3개가 비어 있다) |

### 4.7 초기화 대상: 라운드 시작과 세트 종료

같은 세트 안에서는 라운드가 바뀌어도 **폼과 증강이 유지**되고, 전투 상태는 매 라운드 새로 시작한다. 세트가 끝나면 폼과 증강도 초기화한다.

| 상태 | 라운드 시작 (같은 세트 안) | 세트 종료 후 다음 세트 시작 |
|---|---|---|
| 체력 | 최대 | 최대 |
| 위치, 속도, 바라보는 방향 | 맵의 시작 위치, 정지 | 같음 |
| 행동 상태와 타이머(공격, 충전, 돌진, 경직, 히트스탑, 연속 명중, 면역, 이동 대시 충전·재사용, 점프 횟수, 대기 중인 눌림) | 모두 초기 상태 | 같음 |
| 에너지와 회복 지연 | 최대, 지연 0 | 같음 |
| 투사체 | 전부 제거 | 같음 |
| 구조물·상자 | 그 라운드 맵의 초기 상태로 다시 만든다 | 같음 |
| 폼별 상태, 증강이 만든 일시 상태(트리거 대기 등) | 초기화 | 같음 |
| **보유 폼, 현재 폼** | **유지.** 라운드 시작 폼은 직전 라운드 종료 때의 현재 폼이다. 직전 선택에서 새 폼을 획득했으면 그 폼으로 시작한다 | **초기화.** 세트 시작 때 비공개로 고른 폼 하나 |
| **증강(획득 목록과 적용 결과)** | **유지** | **초기화** |
| 이번 세트의 선택 횟수와 선택 상태 | 유지 | 초기화 |
| 라운드 점수(세트 안) | 유지(무승부 라운드는 변화 없음) | 초기화 |
| **세트스코어** | 유지 | **유지**(경기 종료 뒤 재시작할 때 초기화) |
| 맵 순환 | 라운드마다 다음 맵 | **이어간다**(세트가 바뀌어도 초기화하지 않는다. 경기 시작·재시작 때 새로 섞는다) |
| 난수 상태 | 유지 | 유지(라운드마다 다시 시드하면 선택지가 반복된다. 경기 시작 때만 시드한다) |

**순서**: 라운드 종료(KO) → 세트가 끝나지 않았으면 패자 선택 → 라운드 시작 초기화 → 카운트다운 → 전투. 세트가 끝나면: 세트스코어 집계 → 경기가 끝나지 않았으면 세트 초기화 → 초기 폼 비공개 선택 → 라운드 시작 초기화 → 카운트다운. 무승부 라운드는 선택 없이 라운드 시작 초기화만 하고 같은 라운드를 다시 한다.

## 5. 증강 규칙과 대안 스위치

### 5.1 대안 스위치는 세 가지뿐

비교에 꼭 필요한 것만 만든다. 이 외의 임시 기본값 대안은 만들지 않고, 튜닝 값으로만 둔다.

| 스위치 | 값 |
|---|---|
| 가드·잡기 | 끔(기본) / 켬 |
| 공격 에너지 | 켬(기본) / 끔 (M1 봇 매트릭스 비교용, 이후 유지) |
| 현재 폼 표시 | 상시 표시 / 준비·발동 때만 표시 / 최소 표시(작은 마크). 연출 계층의 옵션이라 시뮬레이션 체크섬에 영향이 없어야 한다 |

폼마다 **선딜 동작은 반드시 구분되게** 그린다(어느 표시 방식이든 필요한 조건이다).

### 5.2 전환 지표 (CP21에서 수집)

한 판당 전환 횟수, 공격 직후 짧은 시간 안에 전환한 비율, 상대의 선딜이 시작된 뒤 전환까지의 반응 시간 분포, 두 폼을 오가는 진동 패턴. 문제를 판정하는 기준값은 정하지 않는다. 기록하고 보고만 한다.

### 5.3 증강의 구조와 적용 규칙

증강은 **수정자 묶음**이다. 수정자는 네 종류다.
① 수치 변경(가산) ② 배율(곱) ③ 속성 플래그(설정·해제) ④ 동작 대체 또는 추가(이동 덮어쓰기, 트리거)

**적용 순서(고정)**: ① → ② → ③ → ④ 단계 순으로 적용한다. 같은 단계 안에서는 증강 번호(ID) 순이다. **획득한 순서에 의존하지 않는다.** 최종 결과는 획득 순서의 모든 순열에서 같아야 한다.

**동작 간 충돌과 우선순위**

| 충돌 | 규칙 |
|---|---|
| 같은 플래그를 서로 반대로 설정(켜기 대 끄기) | 증강마다 `Priority`(정수)를 둔다. 높은 쪽이 이긴다. 동률이면 ID가 작은 쪽이 이긴다 |
| 같은 **동작 슬롯**(예: 이동 방식, 발사 방식)을 대체하는 증강이 둘 이상 | 슬롯마다 하나만 활성이다. `Priority`가 높은 쪽이 슬롯을 차지하고, 진 쪽은 **그 슬롯 효과만** 비활성이며 나머지 효과(수치 등)는 유지한다. 후보 제시 단계에서는 이미 슬롯을 차지한 증강과 충돌하는 증강을 제안하지 않는다(필터). 필터를 우회해 강제로 부여해도 위 규칙대로 결정적으로 해소돼야 한다 |
| 같은 이벤트(예: 적중)에 트리거가 여럿 | 고정 순서: `Priority` → ID. 한 틱 안에서 트리거가 새 트리거를 일으키지 않는다(연쇄 깊이 상한 1) |
| 비용이나 선딜을 바꾸는 증강 | 수치 단계에서 처리하며 최종값은 하한(에너지 비용 0 이상, 선딜 1틱 이상 등)으로 자른다 |
| 상성에 영향을 주는 증강 | 해석기(4.1)는 증강이 적용된 **최종 속성**으로 판정한다. 개수가 아니라 효과가 실제로 바꾼 속성이 상성을 바꾼다 |
| 한 증강이 다른 증강의 수정 대상을 없앰(**무의미 조합**) | 증강은 자신이 수정하는 대상(`Targets`)과 없애는 대상(`Removes`)을 데이터로 선언한다. 한 증강의 `Removes`가 다른 증강의 `Targets`와 겹치면 무의미 조합이다. 후보 제시 단계에서 이미 가진 증강과 무의미 조합이 되는 후보는 제안하지 않는다(필터). 강제로 부여하면 `Targets`를 잃은 쪽을 **휴면**시킨다: 효과가 적용되지 않고, 에너지·상태·속성에 아무 영향이 없으며, 결정적이다. 예: 충전 시간 단축(`Targets`=충전 단계)과 충전 생략(`Removes`=충전 단계) |

### 5.4 M2의 대표 증강 4개 (이름과 수치는 임시)

서로 다른 작동 방식을 대표한다. **개수는 늘리지 않는다.**

| 방식 | 폼 | 증강 | 시험하는 것 |
|---|---|---|---|
| 수치 변형 | 가위 | **돌진 속도 배율**(예: +20%). 충전한 돌진에도, 즉발 돌진에도 곱해진다 | 파이프라인 ②단계, 즉발 돌진과 **함께 유효한 누적** |
| 속성 뒤집기 | 바위 | **철갑탄**: 투사체의 `Reflectable`을 거짓으로 | ③단계, 해석기, **보에 대한 상성 변화** |
| 이동 덮어쓰기 | 가위 | **즉발 돌진**: 충전 단계를 없애고 누른 틱에 발사한다. 발사 속도는 고정값(`InstantLungeSpeed`), 비용은 발사 비용과 같고, 지형은 그대로 막힌다 | 동작 슬롯 대체(슬롯: 가위 발사 방식), `Removes`=충전 단계 |
| 적중 트리거 | 보 | **적중 시 에너지 일부 환급** | 트리거 순서와 연쇄 상한 |

**조합 정리**
- 이전 초안의 "충전 시간 단축"은 즉발 돌진이 충전 단계를 없애면 효과가 무의미해지므로 **돌진 속도 배율로 바꿨다.**
- 같은 폼에서 두 효과가 **함께 유효한** 조합은 **가위의 돌진 속도 배율 + 즉발 돌진**이다. 속도 배율이 즉발 돌진의 고정 속도에도 곱해지므로 두 효과가 모두 살아 있다.
- 바위와 보는 M2에서 증강이 하나씩이라 누적 조합이 없다(M3에서 확장).
- **실제 선택으로 만들 수 있다**: 가위만 가진 파이터의 첫 선택지는 바위 획득, 보 획득, 가위 증강 두 개로 정확히 네 개다. 가위 증강 하나를 고르면 다음 선택지에 나머지 가위 증강이 남아 있어서, 한 세트 안에서 두 증강을 누적할 수 있다.
- 무의미 조합 규칙(5.3)은 실제 증강 네 개로는 만들어지지 않는다. 이 규칙과 슬롯 충돌 규칙은 **테스트 전용 증강 데이터**로 검사한다(제품에 포함하지 않으며 실제 증강 수는 늘리지 않는다).
- 관통 증강(`PierceFighter`, `PierceProp`)과 벽 통과 같은 지형 상호작용 증강은 M3로 미룬다.

### CP18. M1: 파이터별 폼 기반

**범위**
- `CombatMode`를 읽는 곳(`FighterCombat`의 분기, `FighterMovement`의 착지 분기, 몸통 공격성 계산 등)을 **파이터별 폼 상태**로 옮긴다. 폼은 가위(돌진), 보, 바위 세 가지다(바위와 보의 실제 공격은 CP19~20에서 채운다. 이 CP에서는 폼 상태와 분기 틀을 만든다).
- 가드·잡기를 끄는 스위치. 이미 있는 `GrabEnabled`를 활용하고 가드 스위치를 더한다. 꺼진 상태에서는 해당 입력을 무시한다.
- 공격 에너지: 풀과 회복 지연 타이머를 파이터 상태에 넣고(체크섬과 `Visit` 포함), 4.4의 규칙대로 구현한다. 공격을 시작하는 곳(`StartCharge`, `StartAttack`, `StartGrab`)에서는 **확인만** 하고, **소비는 폼별 소비 시점**에서 한다(가위는 `Launch`에서 발사할 때, 보와 잡기는 시작할 때, 바위는 CP19의 발사 때). 취소와 발사 시 부족의 처리도 4.4대로 구현한다. 이동 대시의 몸통 공격성 가중치를 0으로 둔다. HUD에 작은 에너지 표시를 더한다.
- 시나리오와 `SimConfig`에서 폼과 스위치를 지정할 수 있게 한다.
- 입력 기록 형식 버전을 올린다(2절).

**검증 기준**
- **CP18-1 [T]** **(A) 기존 행동 회귀**: 폼을 가위로, 가드·잡기를 켠 설정에서 기존 시나리오와 기존 테스트가 통과한다. 의도한 변경 목록이 로그에 있다.
- **CP18-2 [T]** **(B) 새 구조의 결정론**: 3600틱 두 번 실행 체크섬 동일, 저장·복원, SyncTest, 입력 기록 재생 일치.
- **CP18-3 [T]** 에너지 기본: 회복 지연 뒤 회복하고, 바닥나면 공격 시작이 막히며(입력은 버려지고 대기하지 않는다) 이동·점프·이동 대시는 가능하다.
- **CP18-4 [T]** **가위 충전의 확인과 소비**: 에너지가 `LungeCost` 미만이면 충전이 시작되지 않는다. 충전 중 에너지는 변하지 않는다. 발사하면 에너지가 **정확히 `LungeCost`만** 줄어든다(충전을 시작할 때 차감이 없으므로 **이중 차감이 없다**). 최소 충전과 최대 충전 자동 발사에서도 같다. 연속 N회 발사의 총 소비가 N × `LungeCost`다(회복이 없는 조건).
- **CP18-5 [T]** **취소와 발사 시 부족**: 충전 중 피격, 경계 튕김, KO로 끊기면 에너지 감소가 0이다. 테스트에서 충전 중 에너지를 강제로 줄이고 놓으면 발사되지 않고 충전이 취소되며, 에너지는 그대로이고 부족 이벤트가 남는다.
- **CP18-6 [T]** 가드·잡기를 끄면 해당 입력이 무시되고, 켜면 기존과 같다.
- **CP18-7 [T]** 이동 대시의 몸통 공격성이 0이면 에너지가 0인 파이터가 대시 접촉으로 피해를 줄 수 없다.
- **CP18-8 [M]** `Step` 평균 시간, `Step` GC 0, 롤백 8틱 시간 기록(기존 예산 안).
- **CP18-9 [T]** 새 상태 필드가 모두 체크섬 범위에 들어간다(기존 범위 테스트).

### CP19. M1: 투사체와 바위 폼

**범위**
- **투사체 풀**: 파이터당 고정 용량, 시뮬레이션 상태에 포함(체크섬, 저장·복원, `StateDiff`), `Step`에서 GC 0. 풀이 찼을 때의 동작(가장 오래된 것 소멸 또는 발사 불가)은 자체 결정하고 기록한다.
- 4.3의 속성(`Reflectable`, `PierceFighter`, `PierceProp`)과 지형·경계·구조물·상자와의 기본 관계. 터널링이 없어야 한다.
- 바위 기본공격: 선딜, 발사 방향(8방향), 속도, 피격 시 피해·넉백·히트스탑(공통 틀 재사용). 에너지는 4.4대로 **동작을 시작할 때 `ShotCost` 이상인지 확인**하고 **발사할 때 한 번 소비**한다(취소, 부족 처리 포함).
- 연출: 투사체 그림(코드로 그린 도형), 발사·적중 이벤트와 효과음(합성).

**검증 기준**
- **CP19-1 [T]** 풀 한도: 한도까지 쏘고 초과해도 크래시나 상태 오염이 없고, 정한 동작대로 처리된다.
- **CP19-2 [T]** 결정론, 저장·복원, SyncTest(투사체가 날아다니는 장면 포함), 입력 기록 재생.
- **CP19-3 [T]** 터널링 없음: 최대 속도 투사체로 두께 0.5의 지형·발판·상자를 여러 각도에서 맞혀도 통과가 없다.
- **CP19-4 [T]** 지형, 경계, 구조물, 상자에 닿았을 때의 반응이 4.3대로다. 데이터로 `PierceFighter`·`PierceProp`을 켠 투사체가 각각 파이터와 구조물·상자를 통과하되 지형은 막힌다.
- **CP19-5 [T]** 바위의 에너지: `ShotCost` 미만이면 발사 동작이 시작되지 않고, 발사하면 정확히 한 번만 소비되며, 선딜 중 피격으로 끊기면 소비가 없고, 발사 틱에 부족하면 발사하지 않고 취소한다.
- **CP19-6 [T]** 대칭성(미러 시나리오).
- **CP19-7 [M]** 투사체 풀이 가득 찬 장면에서 `Step`, 롤백 8틱, GC 기록.

### CP20. M1 끝: 보 폼, 속성 해석기, 3×3 상호작용

**범위**
- **보**: 동결해 둔 모드 B 코드를 기본공격 하나(앞 휘두르기)로 줄여 재사용한다. 4.2대로 **활성 판정이 겹칠 때만** 투사체를 반사한다.
- **속성 해석기**: 4.1을 구현한다. 폼 쌍별 분기가 아니라 속성 비교로 처리하고, 두 파이터의 판정은 기존처럼 같은 스냅숏에서 동시에 계산하고 동시에 적용한다(번호 우선순위 없음).
- 봇(`CombatBot`)이 세 폼을 각각 쓸 수 있게 한다. 이 CP에서 봇의 폼은 시드로 고정한다. 목표는 진행 확인이지 실력이 아니다.
- **M1 봇 매트릭스**: 에너지 켬/끔 × 폼 쌍(자기 대전 포함 3×3) × 맵 6개 × 시드 6 × 2분.
- `docs/progress/M1-summary.md`: 발견한 문제, 알려진 문제, 마음에 걸리는 임시 기본값. 승률 수치는 방향 지표로 기록만 한다. 이 요약을 쓰고 **멈추지 않고 CP21로 간다.**

**검증 기준**
- **CP20-1 [T]** 상호작용 표(4.1)의 **모든 칸**(폼 쌍 + 공격하지 않는 상태 + 같은 종류끼리)을 결정적 시나리오 테스트로 확인한다. 결과의 종류(피해, 기절, 반사, 중단, 상쇄)와 대상이 표와 같다.
- **CP20-2 [T]** 보의 반사 조건: 활성 판정이 아닌 선딜·후딜에는 반사하지 않고, `Reflectable`이 거짓이면 반사하지 않고 투사체가 그대로 진행해 보를 일반 명중시키며, 반사 뒤 소유자가 바뀌고 반사된 투사체가 원래 소유자를 맞힌다. 연속 반사 상한과 한 활성 판정당 한 번 규칙이 동작한다.
- **CP20-3 [T]** 속성 구분: 관통 투사체가 파이터는 맞히고 계속 가고, 구조물·상자는 통과 여부를 따로 갖고, 관통 투사체도 보의 활성 판정에는 반사된다.
- **CP20-4 [T]** 동시 처리와 대칭성: 같은 틱에 서로의 공격이 닿아도 번호 우선순위 없이 같은 결과가 나오고, 미러 시나리오의 결과가 일치한다.
- **CP20-5 [T]** 결정론, SyncTest(세 폼이 섞인 장면), 입력 기록 재생.
- **CP20-6 [M]** 봇 매트릭스: 모든 조합에서 **불변식 위반 0**(경기장 이탈, NaN, 1초를 넘는 겹침 등), 라운드가 끝나지 않는 조합 없음. 라운드 길이 분포와 폼 쌍별 승률은 기록만 한다(합격 기준 아님). 투사체 도배로 라운드가 끝나지 않으면 붕괴로 보고 튜닝 두 번까지 시도한다.
- **CP20-7 [M]** 가드·잡기를 끈 상태의 벽꽝/분, 경계·구조물·상자 데미지 비중을 `baseline-cp16.md`와 나란히 표로 정리한다(지형 축이 얼마나 줄었는지 확인).

### CP21. M2: 폼 전환

**범위**
- 보유 폼 상태(비트마스크), 현재 폼, 전환 입력(새 입력 비트 또는 키. 키 배치는 자체 결정하고 로그에 적는다), 4.5의 규칙.
- 5.2의 전환 지표 수집.
- 현재 폼 표시 세 가지(5.1) 연출 옵션과 키 전환. 폼별로 구분되는 선딜 동작.
- 봇의 전환: 단순 규칙(예: 상대의 현재 폼을 보고 카운터 폼을 일정 확률로 선택).

**검증 기준**
- **CP21-1 [T]** 전환이 후딜과 선딜을 우회하지 않는다: 공격 중·후딜 중·경직 중의 전환 입력이 무시되고, 가위 돌진이 끝난 직후 전환해 공격해도 에너지와 새 폼의 선딜이 적용된다.
- **CP21-2 [T]** 폼별 상태가 전환해도 보존된다. 에너지는 전환으로 변하지 않는다.
- **CP21-3 [T]** 히트스탑 중 눌린 전환은 히트스탑이 끝난 뒤 처리된다.
- **CP21-4 [T]** 결정론, SyncTest, 입력 기록 재생(전환 포함).
- **CP21-5 [T]** 현재 폼 표시 세 가지 모두 시뮬레이션 체크섬에 영향이 없다(연출 켬/끔 비교).
- **CP21-6 [T]** 전환 지표 수집이 동작하고 봇 경기에서 값이 기록된다.
- **CP21-7 [S]** 폼별 선딜 구분 캡처와 표시 방식 세 가지 캡처(필요한 만큼만, 960×540 이하로 확인).

### CP22. M2: 라운드·세트·경기, 패자 선택

**범위**
- 라운드·세트·경기 상태 기계(3절). 세트 시작의 비공개 동시 초기 선택, 라운드 종료 뒤 **패자만** 선택하는 단계(기존 `RoundTransition` 훅 활용), 선택지 최대 4개(이 CP에서는 **폼 획득만 동작**하고 증강 선택지 자리는 CP23이 채운다), 세트 승자 집계, 경기 종료, 재시작.
- **라운드 시작 초기화와 세트 종료 초기화를 4.7대로 구분해 구현한다.** 상태를 전투 부분과 세트 부분(폼, 증강, 점수, 선택 횟수, 맵 순환)으로 나눠 비교할 수 있게 한다.
- 선택은 시뮬레이션 입력으로 흘려 보내 리플레이와 롤백에 포함한다.
- 선택 화면: 선택지는 **패자 쪽 영역에만** 보이고, 선택 결과는 표시하지 않는다(1절의 한계). 짧은 영문과 코드로 그린 아이콘.
- 코드의 `MatchState` 이름을 3절대로 정리한다(자체 결정).
- 봇의 선택은 시드 무작위.

**검증 기준**
- **CP22-1 [T]** 상태 전이: 3승으로 세트 획득, 3:0, 3:2, 경기 종료(2세트 선승), 경기 종료 뒤 재시작이 모두 정의대로 동작한다.
- **CP22-2 [T]** 패자만 선택한다(승자는 선택이 없다). 무승부 라운드에는 점수와 선택이 없다.
- **CP22-3 [T]** 폼 획득이 반영돼 전환 가능한 폼 목록이 늘어난다. 이미 가진 폼은 선택지에 나오지 않는다.
- **CP22-4 [T]** **라운드 시작 초기화**: 라운드가 끝나고 다음 라운드를 시작하면 4.7의 라운드 초기화 대상이 모두 초기 상태다(체력 최대, 시작 위치·정지, 행동 Idle과 모든 타이머 0, 에너지 최대와 지연 0, 투사체 0개, 구조물·상자가 새 맵의 초기 상태). 폼, 증강, 선택 횟수, 라운드 점수, 세트스코어, 난수 상태는 그대로다.
- **CP22-5 [T]** **잔여 상태 누수 없음**: 봇이 격하게 싸운 라운드(투사체가 날고, 충전·돌진·경직·히트스탑 중이고, 구조물이 흔들리는 상태)가 끝난 직후 다음 라운드를 시작한 상태의 **전투 상태 필드**가, 같은 맵·같은 폼·같은 증강으로 새로 시작한 라운드의 전투 상태 필드와 일치한다. 세트 부분(폼, 증강, 점수, 선택 횟수, 맵 순환)은 비교에서 제외하고 4.7의 "유지" 값과 따로 비교한다.
- **CP22-6 [T]** **라운드 시작 폼**: 패자가 새 폼을 획득했으면 다음 라운드를 그 폼으로 시작하고, 증강을 골랐거나 승자이면 직전 현재 폼으로 시작한다. 라운드 중에 전환해 둔 폼이 다음 라운드로 이어진다.
- **CP22-7 [T]** **세트 종료 초기화**: 세트가 끝나고 다음 세트가 시작되면 폼, 증강, 선택 횟수, 라운드 점수가 초기화되고(초기 폼은 새로 비공개로 선택), 세트스코어와 맵 순환 위치는 유지되며, 라운드 시작 초기화도 함께 적용된다. 경기 종료 뒤 재시작이면 세트스코어와 맵 순환도 초기화된다.
- **CP22-8 [T]** **무승부 라운드**: 점수와 선택 없이 같은 라운드를 다시 하고(5라운드 한도에 세지 않는다), 라운드 시작 초기화만 적용되며 폼과 증강은 유지된다.
- **CP22-9 [T]** 같은 시드면 선택지가 같다. 선택 단계를 포함한 SyncTest와 입력 기록 재생 최종 체크섬이 일치한다.
- **CP22-10 [T]** 라운드마다 맵이 교체되는 기존 순환과 호환된다.
- **CP22-11 [M]** 봇이 경기 전체(2세트 선승)를 시드 6개로 불변식 위반 0, 중단 없이 완주한다. 경기 길이를 기록한다.
- **CP22-12 [S]** 선택 화면과 경기 종료 화면 캡처.

### CP23. M2: 증강 틀

**범위**
- 5.3의 수정자 파이프라인(고정 적용 순서, 충돌·우선순위), 증강 데이터 형식, 후보 제시(시드 추첨 + 슬롯 점유 필터), 누적. CP22의 선택 단계에 증강 선택지를 연결한다.
- 5.4의 대표 증강 4개(가위 2, 바위 1, 보 1).
- 증강이 발동하는 순간 이름 아이콘을 짧게 표시한다(평소에는 표시하지 않는다).
- 증강 상태를 시뮬레이션 상태에 포함한다(체크섬, 저장·복원, `StateDiff`).

**검증 기준**
- **CP23-1 [T]** **순서 독립성**: 증강 N개를 가능한 모든 획득 순서(순열)로 부여해도 최종 속성과 수치가 같다(실제 증강 4개와 테스트 전용 증강 모두).
- **CP23-2 [T]** **충돌·우선순위**: 플래그 반대 설정, 같은 동작 슬롯 대체, 동시 트리거를 **테스트 전용 증강 데이터로** 강제로 부여해도 5.3의 규칙대로 결정적으로 해소된다(우선순위, 동률 시 ID, 슬롯 하나만 활성, 진 쪽의 다른 효과는 유지).
- **CP23-3 [T]** 트리거 연쇄 깊이 상한이 지켜지고, 수치 하한(비용 0 이상, 선딜 1틱 이상)이 적용된다.
- **CP23-4 [T]** **증강이 상성을 바꾼다(철갑탄 전후 검사)**: 같은 시나리오를 증강만 바꿔 두 번 실행한다. 평지에서 마주 선 바위(P1)와 보(P2)가 있고, P1이 발사하며, P2는 투사체가 닿는 틱에 근접 활성 판정이 겹치도록 휘두른다(타이밍은 설정값에서 계산한다).
  - **증강 전**(철갑탄 없음): 반사 이벤트가 발생하고, 투사체 소유자가 P2로 바뀌며 진행 방향이 반대가 되고, P2는 이 투사체로 피해를 받지 않으며, 반사된 투사체가 P1을 맞혀 P1의 체력만 줄어든다.
  - **증강 후**(P1에 철갑탄): 반사 이벤트가 없고, 소유자는 P1 그대로이며, 투사체가 보의 활성 판정을 지나 P2를 일반 명중(피해, 넉백, 경직)시켜 P2의 체력만 줄고 P1의 체력은 그대로다.
  - **대조군**: 철갑탄 대신 다른 증강 하나, 또는 `Reflectable`을 건드리지 않는 증강 둘을 P1에 붙이면 증강 전과 같은 결과(반사)가 나온다. 개수가 아니라 `Reflectable`을 바꾼 효과가 상성을 바꾼다는 것을 확인한다.
  - 두 실행의 차이는 투사체의 `Reflectable` 값 하나이며, 해석기 코드는 같다(폼 쌍별 분기가 없다).
- **CP23-5 [T]** **누적 A+B가 함께 유효**: 가위에 돌진 속도 배율과 즉발 돌진을 둘 다 붙이면 ① 충전 단계 없이 누른 틱에 발사되고 ② 발사 속도가 `InstantLungeSpeed` × 배율이며(어느 하나만 붙였을 때보다 큰 값) ③ 어느 것을 먼저 얻어도 결과가 같고 ④ 에너지가 `LungeCost` 한 번만 소비된다. 속도 배율만 붙인 충전형 가위는 충전 속도 × 배율이다.
- **CP23-6 [T]** **무의미 조합**: 테스트 전용 데이터(충전 시간 단축 + 충전 생략)로 후보 필터가 이 조합을 걸러내고, 강제로 부여하면 의존하는 쪽이 휴면돼(효과 없음, 에너지·상태·속성 변화 없음) 결정적이며 순서와 무관하다.
- **CP23-7 [T]** **후보 제시와 실제 선택**: 같은 시드면 후보가 같다. 가위만 가진 파이터의 첫 선택지가 정확히 4개(바위 획득, 보 획득, 가위 증강 2개)이고, 가위 증강 하나를 고르면 다음 선택지에 나머지 가위 증강이 있다. 슬롯 충돌 필터는 테스트 전용 데이터로 확인한다.
- **CP23-8 [T]** 결정론, SyncTest, 입력 기록 재생(증강 상태 포함), 대칭성.
- **CP23-9 [M]** 증강이 붙은 봇 경기가 불변식 위반 0으로 완주한다. `Step`, 롤백 8틱, GC 기록.
- **CP23-10 [S]** 증강 발동 아이콘과 선택 화면 캡처.
